# Расширения и граница ядро/UI

Решение P11.5 от 04.11.2026: сохранить собственное Swift-ядро и AppKit UI; проверять расширяемость отдельным JSON-процессом, не включать части FAR/far2l в продукт. Прототип проверяет собственную границу данных. Он не является прототипом встраивания ядра FAR и не доказывает возможность переноса его плагинов.

## Проверенные исходники

Официальный FAR закреплён на `1a6b02544b339615232078e0551463ef15b73ff9`. [PluginStartupInfo, plugin.hpp:2624–2664](https://github.com/FarGroup/FarManager/blob/1a6b02544b339615232078e0551463ef15b73ff9/far/plugin.hpp#L2624) передаёт плагину таблицу функций управления панелями, диалогами, экраном, редактором, просмотрщиком, макросами и настройками. [Экспорты:3288–3326](https://github.com/FarGroup/FarManager/blob/1a6b02544b339615232078e0551463ef15b73ff9/far/plugin.hpp#L3288) используют `WINAPI`, `HANDLE` и структуры для `OpenW`, `GetFindDataW`, `GetFilesW`, `PutFilesW`, обработки ввода и событий. Это большой синхронный контракт с UI и временем жизни объектов; таблица имён функций не является переносимым интерфейсом AppKit. Бинарные Windows DLL не поддерживаются.

far2l исследован отдельно на `1bd345fe9708f94e03209bd443c2ca2303b39c25`. [CMakeLists.txt:206–280](https://github.com/elfmz/far2l/blob/1bd345fe9708f94e03209bd443c2ca2303b39c25/CMakeLists.txt#L206) собирает WinPort, far2l и отдельные WX/SDL/TTY backend. [WinPort.h:60](https://github.com/elfmz/far2l/blob/1bd345fe9708f94e03209bd443c2ca2303b39c25/WinPort/WinPort.h#L60) содержит запуск через `WinPortMain`; [строка 169](https://github.com/elfmz/far2l/blob/1bd345fe9708f94e03209bd443c2ca2303b39c25/WinPort/WinPort.h#L169) и далее — управление консольными дескрипторами и отложенной перерисовкой. Наличие backend отделяет отображение консоли, но не доказывает наличие готовой модели документов/панелей для AppKit. Встраивание потребовало бы отдельного исполняемого прототипа и измерения зависимостей, а не замены библиотеки UI.

## Собственный проверяемый прототип

[ExtensionAPI.swift](../Sources/FarCore/ExtensionAPI.swift) содержит публичные Codable request/response и `ExtensionHost`; [text-tools.py](../Examples/Extensions/text-tools.py) — отдельную реализацию API v1. Процесс получает один JSON из stdin и возвращает один JSON в stdout. Запрос содержит версию, вид расширения, текст и снимок элементов; ответ — версию, вид, заголовок, текст либо строки `label/value`. Виды: `command`, `panel`, `viewer`, `editor`. Панель пока означает информационные строки, а не файловую систему с навигацией/копированием FAR. Редактор возвращает предлагаемую замену текста; запись на диск остаётся у приложения.

Помимо собственных примеров SHA-256 текста, статистики панели и форматирования JSON, API проверяется переносом ограниченного поведения двух конкретных штатных расширений FAR:

| Расширение и первичный источник | Переносимый полезный поднабор | Отличия от полного плагина |
| --- | --- | --- |
| **EditCase**, [EditCase.cpp:412–460](https://github.com/FarGroup/FarManager/blob/1a6b02544b339615232078e0551463ef15b73ff9/plugins/editcase/EditCase.cpp#L412), [справка:7](https://github.com/FarGroup/FarManager/blob/1a6b02544b339615232078e0551463ef15b73ff9/plugins/editcase/ECaseEng.hlf#L7) | Режимы `editcase-upper` / `editcase-lower`: изменение регистра латинских ASCII-букв переданного текста; остальные символы и переводы строк сохраняются | FAR работает с выделением или текущим словом и использует `MyIsAlpha`/`FSF.LUpper`/`FSF.LLower` по символам wchar. Перенос намеренно не обещает Unicode/локальные правила FAR, Title/Toggle/Cyclic, меню и Lua-вызовы плагина |
| **Align**, [Align.cpp:310–353](https://github.com/FarGroup/FarManager/blob/1a6b02544b339615232078e0551463ef15b73ff9/plugins/align/Align.cpp#L310), [параметр по умолчанию:60](https://github.com/FarGroup/FarManager/blob/1a6b02544b339615232078e0551463ef15b73ff9/plugins/align/Align.cpp#L60) | Режим `align`: выравнивание допустимых коротких ASCII-строк до 75 символов добавлением пробелов между словами, равными долями с остатком слева | Только строки без табуляции, начальных/конечных пробелов, с двумя или более словами через одиночный ASCII-пробел. Остальные строки остаются неизменными. Нет объединения/переноса абзацев, SmartMode, диалога ширины, прямого доступа к выделению FAR |

Это независимые реализации поведения по прочитанным алгоритмам, не компиляция исходников FAR. Для Align при ширине 20 тестовый принцип распределения: `one two three` → `one     two    three`; рабочая ширина прототипа 75. API получает снимок текста и возвращает результат без изменения исходного документа. Проверки [ExtensionAPITests.swift](../Tests/FarCoreTests/ExtensionAPITests.swift) используют публичные типы отдельно от UI и проверяют результаты, версию, тип ответа, сбой процесса, некорректный JSON, тайм-аут и превышение объёма. Результат запуска проверок следует фиксировать в приёмке; наличие теста само по себе не означает его успешное выполнение.

Граница ядро/UI: FarCore владеет проверкой протокола и запуском процесса, AppKit — выбором данных, показом результата и решением применить редакторскую правку. Сбой процесса не должен завершать приложение. Значения по умолчанию — 3 секунды и 1 МиБ входа/суммарного вывода; неподдерживаемая версия отклоняется. Прототип запускается по явному действию, а не путём исполнения найденных конфигураций. Это изоляция сбоя, **не ограничение прав ОС**: выбранная программа выполняется с правами пользователя. Дочерние процессы и полноценная система разрешений не представлены как завершённая модель безопасности.

## Лицензии и решение о повторном использовании

Прочитанный [LICENSE FAR](https://github.com/FarGroup/FarManager/blob/1a6b02544b339615232078e0551463ef15b73ff9/LICENSE#L1) — BSD 3-Clause: сохранение уведомлений и условий при распространении исходников/бинарников, запрет использования имён правообладателей для продвижения без разрешения. [LICENSE.txt far2l](https://github.com/elfmz/far2l/blob/1bd345fe9708f94e03209bd443c2ca2303b39c25/LICENSE.txt#L1) содержит GNU GPL v2. Это проверенные сведения о файлах лицензий, а не утверждение, что каждый вложенный компонент имеет те же условия. Перед любым заимствованием нужен список конкретных файлов и их уведомлений/зависимостей; текущий прототип код этих проектов не копирует и не линкует.

Выбор собственного API подтверждён узким обменом данными без экранных буферов, Win32 ABI и указателей UI. Обратная сторона: отсутствуют исходная/бинарная совместимость FAR, полнофункциональные файловые панели расширений, постоянные сессии плагинов и произвольные callback API редактора. P11.5 завершает решение о текущем направлении, но не закрывает эти ограничения и не означает перенос полного набора возможностей плагинов EditCase/Align или других расширений FAR.
