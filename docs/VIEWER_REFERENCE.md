Архитектура адаптирована к macOS: AppKit показывает ограниченную страницу, а чтение и поиск выполняются в фоне через контракт источника байтов. Локальный провайдер не открывает файл на запись. Архивные и сетевые файлы просматриваются через полностью загруженные приватные рабочие копии; прямое потоковое чтение этих провайдеров остаётся отдельной задачей.

F6 использует редактор этапа 6 до 8 МиБ с теми же шестью кодировками: UTF-8, UTF-16 LE/BE, Windows-1251/1252, Latin-1. Байтовая позиция отображается в UTF-16 позицию редактора и обратно с учётом BOM и целого Unicode-скаляра. Редактор требует обратимого декодирования; неправильные последовательности и неопределённые байты кодовой страницы дают отказ. Кодировка, BOM и смешанные окончания строк сохраняются при обычной записи; переход из просмотра не выполняет скрытого преобразования. Несохранённый буфер при возврате к просмотру требует решения пользователя. Save As, конфликты, восстановление и адаптации описаны в [EDITOR_REFERENCE.md](EDITOR_REFERENCE.md).

Целые слова доступны для текста и regex: границы проверяются по буквам, цифрам, комбинируемым знакам и подчёркиванию Unicode, включая границы загружаемых блоков. Для hex флажок не применяется. Это явная Unicode-адаптация, без полного набора настраиваемых разделителей FAR.

«Следить за файлом» обновляет конец локального файла раз в секунду через новый неизменяемый источник и блок до 64 КиБ. Усечение и атомарная замена файла поддержаны; проверки изменения источника остаются включены. Если файл меняется во время чтения, повтор выполняется при следующем опросе. Поиск и явный переход выключают слежение; для архивных, сетевых и переданных провайдеров команда скрыта. В FAR обновление при простое и удержание последней страницы проверены в [viewer.cpp:1640](https://github.com/FarGroup/FarManager/blob/1a6b02544b339615232078e0551463ef15b73ff9/far/viewer.cpp#L1640); отдельный флажок — адаптация macOS.

Для рабочей копии архива или сервера F6 из редактора открывает сохранённые локальные байты и временно скрывает тот же редактор. Обратный F6 возвращает исходный экземпляр редактора с байтовой позицией; окно отдельной записи в архив/на сервер сохраняет связь с исходным источником. Оба окна удерживают рабочую папку. Закрытие сеанса завершает связанный просмотр; отдельные просмотры продолжают удерживать собственную папку. Несохранённые правки требуют решения перед переходом. Save As в другой файл отделяет его от обратной записи; просмотр такого файла остаётся локальным. Ни один F6 не запускает запись в архив или загрузку на сервер.

Полный паритет пока не заявлен. Отдельно остаются выделение через несколько загруженных страниц, полный набор кодовых страниц FAR и расширенная настройка клавиш. Ограничение редактора 8 МиБ не ограничивает постраничный просмотр больших файлов; прямое потоковое чтение архивных/сетевых источников остаётся отложенным, просмотр их рабочих копий реализован.

Фактическая приёмка и состояние пунктов P5 фиксируются после проверки в [ACCEPTANCE.md](ACCEPTANCE.md) и [spec.md](../spec.md).


Дополнение R11.2, 04.11.2026: дамп и соседние файлы сверены с тем же закреплённым commit FAR. [`ViewerMode` в FarRus.hlf.m4](https://github.com/FarGroup/FarManager/blob/1a6b02544b339615232078e0551463ef15b73ff9/far/FarRus.hlf.m4#L3001) отличает дамп от hex: нет интерпретации строк, одна позиция на кодовую единицу; UTF-8 занимает позиции ведущего байта и `›` для продолжений, UTF-16 — по два байта. [`txt_dump` / `ShowDump`](https://github.com/FarGroup/FarManager/blob/1a6b02544b339615232078e0551463ef15b73ff9/far/viewer.cpp#L844) подтверждают это поведение. В FarForMac дамп читает ограниченную страницу 64 КиБ, включая BOM; строки формируются по 80 кодовым единицам. Управляющие символы CR/LF/Tab/NUL показаны знаками Unicode Control Pictures, DEL — `␡`; C1, BOM, разделители и форматирующие символы Unicode (включая управление направлением текста) — `�`. Недопустимые последовательности помечаются, исходные байты остаются доступны в hex. AppKit не воспроизводит отдельные UTF-16-суррогаты: допустимая пара показывается целым символом и `›`, каждый с отдельной байтовой позицией. Ширина emoji, CJK и комбинируемых знаков зависит от шрифта; точная консольная геометрия FAR остаётся ограничением.

Shift+F4 и список режимов выбирают текст / hex / дамп. F4 включает hex и возвращается в последний основной режим (текст или дамп). F2 в тексте управляет переносом; из дампа переходит в текст, из hex — в режим, противоположный основному. Режим дампа сохраняется в прежней истории с совместимым необязательным полем.

[`KEY_ADD` / `KEY_SUBTRACT`](https://github.com/FarGroup/FarManager/blob/1a6b02544b339615232078e0551463ef15b73ff9/far/viewer.cpp#L1683) используют список имён просмотра FAR, сохраняют позицию перед открытием соседнего файла. FarForMac захватывает порядок видимых обычных файлов локальной панели при F3. Цифровые + / − и две явные кнопки открывают соседний файл в том же окне без обхода по кругу; каталоги, ссылки и специальные файлы исключены, скрытые фильтром файлы не добавляются. Ссылка под курсором открывается отдельно без списка соседей. Изменение сортировки или пути исходной панели не меняет захваченный порядок. Для каждого пути запоминается версия файла; изменение/замена/удаление/переназначение ссылки дают отказ, без автоматического пропуска к следующему файлу. Открытие и чтение первой страницы выполняются в фоне; отмена или ошибка сохраняют прежний файл, позицию, выделение и индекс списка. Успех обновляет заголовок, путь, контекст макросов, историю/закладки и цель F6; позиция соседа восстанавливается только для той же версии. Список применяется только при открытии из локальной панели: история, отдельные источники, архивные и сетевые рабочие копии не получают произвольных соседей из временной папки.


Дополнение R11.3, 04.11.2026: нестрогий поиск сверён непосредственно с [`fuzzy_searcher_impl::normalize`](https://github.com/FarGroup/FarManager/blob/1a6b02544b339615232078e0551463ef15b73ff9/far/string_utils.cpp#L286), [`find_in`](https://github.com/FarGroup/FarManager/blob/1a6b02544b339615232078e0551463ef15b73ff9/far/string_utils.cpp#L327), [`init_searcher`](https://github.com/FarGroup/FarManager/blob/1a6b02544b339615232078e0551463ef15b73ff9/far/string_utils.hpp#L223) и встроенными [тестами нормализации FAR](https://github.com/FarGroup/FarManager/blob/1a6b02544b339615232078e0551463ef15b73ff9/far/string_utils.cpp#L589). Это поиск подстроки после преобразования Unicode, без расстояния редактирования и без допуска опечаток. FAR сначала раскрывает лигатуры через Windows FoldString, затем раскладывает составные/совместимые формы и цифры и удаляет диакритические/неинтервальные/гласные знаки, кроме классифицированных Windows как алфавитные или лексические. Выбор чувствительности к регистру остаётся отдельным, после нормализации. Целые слова в [`SearchAndReplaceString`](https://github.com/FarGroup/FarManager/blob/1a6b02544b339615232078e0551463ef15b73ff9/far/strmix.cpp#L1281) проверяются после возврата к исходным диапазонам.

FarForMac использует общий с редактором `SearchTextFolding`: Unicode NFKD, явные раскрытия Æ/æ, Œ/œ, ß/ẞ, приведение десятичных цифр Unicode к ASCII и удаление комбинируемых знаков без свойства Alphabetic. Нечувствительный регистр использует независимое от пользовательской локали преобразование Foundation. Примеры из исходных тестов FAR — `їёй → іеи`, `Æﬁ → AEfi`, фрактурное `𝔇𝔬𝔯𝔦𝔪𝔢 → Dorime`, `⓪① → 01`, `⅓ → 1⁄3`, `ß → ss`, `ざ → さ` — проверяются автоматически. Это явная адаптация таблиц Windows к Unicode macOS: полная эквивалентность для всех символов, версий Unicode и классификаций C3_LEXICAL не заявляется. Алфавитные гласные знаки, например деванагари, сохраняются; соединители Unicode не удаляются.

Каждая нормализованная UTF-16 единица хранит две исходные 32-битные границы. Общий подготовленный текст ограничен 16 Ми единиц UTF-16; раскрытие сверх предела даёт явную ошибку до добавления очередного символа, без неограниченного роста карт. При пределе карты занимают до 128 МиБ, строка преобразованного текста — до 32 МиБ. Совпадение внутри раскрытия (`s` в `ß`) выделяет исходный символ целиком. В отличие от посимвольного восстановления FAR, FarForMac включает в конец совпадения следующие удаляемые комбинируемые знаки. Это сохраняет цельность видимого акцента при выделении и замене в редакторе. Целые слова проверяются по исходным буквам/цифрам/знакам/подчёркиванию, а байтовые диапазоны просмотра восстанавливаются по карте выбранной кодировки, включая UTF-16, BOM и кодовые страницы.

Просмотр читает страницы до 64 КиБ, удерживает суффикс по длине преобразованного запроса и предыдущий исходный символ для границы слова. Следующая страница может продолжать комбинируемую последовательность; такое совпадение откладывается до уточнения границы. Максимальный накопленный контекст — 262144 единицы UTF-16, включая текущую страницу; превышение (например, чрезмерно длинная цепочка исчезающих знаков) выдаёт явную ошибку неполного поиска, а не отсутствие совпадения. Поддержаны оба направления, перекрывающиеся совпадения, однократный обход по кругу, отмена и проверка неизменности источника. Regex/hex вместе с нестрогим флажком отклоняются явно, запрос только из исчезающих знаков недопустим. Флажок имеет реальное управление в окне, сохраняется вместе с остальными настройками и восстанавливается в истории последних 20 запросов.
