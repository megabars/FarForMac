# Сетевые возможности FarForMac

Состояние на 4 ноября 2026 года; парольный SFTP добавлен после опубликованного 0.7.0. Документ описывает реализованную базу этапа 10 и её границы; полный паритет FAR и полная UI-приёмка всех протоколов не заявлены. P10.3 включает проверенное продолжение обычного WebDAV-файла с сильным ETag в пределах текущего запуска; другие протоколы безопасно перезапускают передачу. Основной план — [spec.md](../spec.md), сопоставление с FAR — [NETWORK_REFERENCE.md](NETWORK_REFERENCE.md), фактические результаты проверок — [ACCEPTANCE.md](ACCEPTANCE.md).

## Протоколы и подключения

| Возможность | SFTP | FTP / явный FTPS | WebDAV HTTP / HTTPS |
| --- | --- | --- | --- |
| Транспорт | Системный OpenSSH, бинарный SFTP v3; удалённый shell не используется | Системная libcurl; MLSD вместо разбора человекочитаемого LIST | URLSession, PROPFIND и операции WebDAV |
| Аутентификация | Выбор: ключ / agent, пароль либо keyboard-interactive/MFA; отдельный режим у каждого перехода. Keychain для фразы ключа используется только в обычном ключевом режиме | Пользователь и пароль | Basic auth |
| Проверка сервера | Отдельный known_hosts приложения; новый отпечаток подтверждается явно, изменённый ключ отклоняется | FTPS проверяет сертификат и имя сервера, защищает управляющее соединение и данные | HTTPS проверяет сертификат и имя сервера |
| Открытая передача | Нет | FTP требует предупреждения перед подключением | HTTP требует предупреждения перед подключением |
| Список / сведения / навигация | Да | Да; сервер должен поддерживать MLSD | Да; PROPFIND Depth 0/1 |
| Файлы: скачать / отправить | Да | Да | Да, GET / PUT |
| Явное переименование / перенос дерева внутри одного подключения, без замены | Да, SFTP RENAME | Отклоняется: RNTO не гарантирует отсутствие перезаписи нового назначения | Да, MOVE с Overwrite:F |
| Создать папку / удалить обычный файл | Да | Да | Да |
| Пообъектное рекурсивное удаление с предварительным просмотром | Да, REMOVE/RMDIR | Да, DELE/RMD | Папки отклоняются: DELETE может рекурсивно удалить появившееся содержимое |
| Условное сохранение существующего файла | Проверка снимка и байтов; атомарного compare-and-swap нет | Проверка снимка и байтов; атомарного compare-and-swap нет | Сильный ETag: PUT с If-Match; без него — проверка снимка/байтов и MOVE |

FTPS означает явный TLS на FTP-порту, а не отдельный неявный FTPS-протокол. Нельзя молча принять неизвестный сертификат либо отключить проверку имени. Положительный сквозной FTPS-сценарий с реально доверенным сертификатом остаётся отдельной проверкой R16; проверка отказа недоверенному сертификату его не заменяет.

SMB доступен через уже смонтированный macOS-том или папку в обычной файловой панели. Прямой SMB-провайдер, обнаружение серверов и управление монтированием не реализованы.

## Команды панели и рабочие копии

Меню **Сеть** создаёт подключение, отключает панель, открывает удалённый путь, обновляет список через существующий сеанс; отдельная команда «Установить новое SSH-соединение» закрывает прежний SSH-сеанс и подключается заново и отменяет работу. Команды **Продолжить скачивание** и **Сбросить незавершённое скачивание** явно повторяют удерживаемое задание или удаляют его приватную частичную копию. Повтор относится к обычным файлам, скопированным с сетевой панели в локальную; отправка, перенос и папки используют новую операцию. В сетевой панели Enter открывает папку или просмотр файла, Tab переключает панель, Esc отключает; курсор и пометки определяют выбранные объекты.

| Команда | Реализованное поведение | Граница |
| --- | --- | --- |
| F3 | Полная загрузка в приватную копию, затем существующий постраничный просмотрщик | Прямого чтения блоков с сервера нет; на локальном диске нужно место для полного файла |
| F4 | Полная загрузка в приватную копию и редактор | Предел редактора 8 МиБ; сохранение редактора меняет только копию |
| «Сохранить на сервер» | Отдельная отправка сохранённой копии после повторной проверки версии и SHA-256 исходного серверного содержимого | Конфликт сохраняет локальные правки; автоматического слияния нет |
| F5 | Копирование между обычной и сетевой панелями; для деревьев — предпросмотр, слияние с выбором пропустить / заменить обычный файл / другое имя | Отправка деревьев: SFTP/WebDAV. FTP/FTPS-отправка дерева отклоняется из-за отсутствия атомарного запрета замены. Передача между разными подключениями не поддержана |
| F6 | Между обычной и сетевой панелью: перенос файлов/деревьев после проверки копий, включая решения конфликтов. Между двумя панелями одного сохранённого SFTP/WebDAV-подключения: серверное перемещение | Отправка дерева: SFTP/WebDAV; скачивание MOVE: SFTP/FTP/FTPS. WebDAV-дерево на источнике не удаляется. Серверное перемещение не заменяет и не сливает назначения; FTP RNTO и разные подключения отклоняются |
| Сеть → Переименовать | Новое имя одного файла/папки SFTP/WebDAV; предварительный просмотр точных путей | Серверная команда без замены; FTP/FTPS отклоняется |
| F7 | Создать удалённую папку | Одна команда, без слияния существующих папок |
| F8 | Чтение и показ плана; затем отдельное подтверждение необратимого удаления. SFTP/FTP: выбранные деревья удаляются по одному объекту от листьев к корню. WebDAV: только файлы | Без Корзины/undo; при изменении, ошибке или отмене выполненные удаления сохраняются, остаток не удаляется автоматически |

Переход F6 из сетевого просмотрщика в редактор сохраняет позицию и кодировку рабочей копии. Обратный F6 из сетевого редактора открывает сохранённую рабочую копию; из просмотра F6 возвращает тот же редактор с позицией и сохранённой связью с сеансом. Это закрывает P5.4; отправка на сервер остаётся отдельной командой. Окно отправки удерживает локальную копию после закрытия редактора; её можно отправить отдельно. Приватные рабочие файлы удаляются при завершении сеанса/последней ссылки и штатном завершении приложения. Восстановление рабочих копий после аварийного завершения не обещается.

## Слияние и перенос каталогов — R16.5/R16.6

F5/F6 для выделения с папкой предлагают новые назначения либо слияние с таблицей конфликтов. Для каждой строки можно пропустить объект, заменить обычный файл или указать другое имя в папке назначения. Папки и ссылки не заменяются. Решения проверяются до отдельного итогового подтверждения; предпросмотр показывает точные копии, замены и пропуски.

F6 сначала публикует и проверяет все копии, затем повторно проверяет исходник и назначение перед удалением каждого исходного файла. Пустые исходные папки удаляются последними нерекурсивной командой. Пропущенные/изменённые объекты остаются; частичный итог показывает пути и причины. Отмена не откатывает выполненную часть. Потеря ответа удаления отмечается как неопределённый результат, который нужно проверить обновлением панели. Подробности и сверка с FAR — [NETWORK_MOVE_REFERENCE.md](NETWORK_MOVE_REFERENCE.md).

Передача ограничена 100000 объектами, 128 уровнями и 1 ТиБ логических данных. Нужен свободный локальный диск для подготовленных копий; файлы потоково проверяются, но дерево готовится до первой публикации. Символические ссылки не копируются. Скачивание отказывает при именах, совпадающих после NFC/сопоставления без регистра, чтобы временная файловая система Mac не объединила разные серверные файлы. Подробности, реальные проверки и ограничения конкурирующих изменений — [NETWORK_DIRECTORY_REFERENCE.md](NETWORK_DIRECTORY_REFERENCE.md).

## Целостность и ограничения операций

Копия публикуется после проверки подготовленных данных. Для переноса источник удаляется после чтения и проверки назначения. Публикация не использует удаление старого назначения как обход отказа rename. Если безопасная для выбранного сценария замена не поддержана сервером, операция сообщает ошибку. При независимой записи другим клиентом FTP/SFTP и WebDAV без сильного ETag сохраняют окно гонки между последней проверкой и rename/удалением; полной транзакционности нет.

Сильный ETag WebDAV используется как серверное условие If-Match при записи. Ответ 412 означает конфликт; локальные изменения остаются доступны. Потеря ответа после публикации может означать уже выполненную запись: перед повтором необходимо проверить текущее состояние сервера. Завершённые файлы при отмене не откатываются.

Копирование дерева ограничено 128 уровнями вложенности, 100000 объектов и 1 ТиБ на выбранное дерево. Дочерние пути и повторяющиеся имена проверяются; символические ссылки и специальные файлы не копируются. Сетевые POSIX-права, владельцы, исходные даты, ACL, xattr и resource forks не переносятся. Рабочие копии используют приватные права 0600/0700, что не означает сохранения метаданных источника.

После прерванной серверной подготовки может остаться `.farmac-upload-UUID`. Общий движок не удаляет такой объект без доказательства владения; приложение не обещает общего отката. SFTP-провайдер отдельно пытается очистить собственный исключительно созданный временный файл при отмене/ошибке. Наличие локального либо удалённого `.part` само по себе не разрешает продолжение передачи.

## Прогресс, повтор и секреты

Фоновые сетевые операции показывают байтовый прогресс, поддерживают отмену и таймаут. Обновление панели переиспользует живой SSH-сеанс вместе с цепочкой переходов; новый сеанс устанавливается отдельной командой. Отключение панели закрывает сеанс, отмена/таймаут/ошибка транспорта сбрасывают его. Следующая явная операция может запросить вход снова. Операции одного провайдера последовательны; сеанс не разделяется между разными экземплярами подключений. Изменение known_hosts или выбранного файла ключа также требует новой аутентификации. [Подробности R16.7](SSH_CONNECTIONS.md). Сетевые задания используют собственное окно операции, а не постоянный журнал локальной очереди.

Ядро P10.3 удерживает только собственный приватный частичный файл в пределах текущего запуска. Для WebDAV с сильным ETag первый GET условный (`If-Match`); перед продолжением заново проверяются все параметры подключения, серверный снимок/ETag, идентичность локального файла, размер, времена изменения и SHA-256 всего полученного префикса. Только после этого отправляются Range и If-Match; изменение версии или подмена префикса требуют новой операции. Перед публикацией проверяются полный размер, свежий серверный снимок и исходный снимок локального назначения. Этот контракт прошёл 18 детерминированных тестов ядра и сквозные проверки прерванного HTTP. Если отмена не позволила закончить проверку префикса, повтор начинает передачу с нуля. После ошибки задание удерживается до явного повтора, сброса или штатного завершения приложения; успешно завершённые объекты повторно не передаются. Слабый ETag, FTP и SFTP безопасно начинают передачу с нуля. Продолжение произвольного `.part`, после перезапуска приложения и без сильного ETag не заявлено.

Профили `~/Library/Application Support/FarForMac/Connections.json` содержат адрес, протокол, имя пользователя, путь, порт, таймаут, путь к SSH-ключу и способ входа SFTP; пароли в JSON не записываются. Старые профили SFTP открываются в режиме ключа/agent. Пароли SFTP/FTP/WebDAV сохраняются в macOS Keychain только по выбору пользователя вместе с параметрами успешно проверенного подключения. Изменение адреса, порта, пользователя, протокола или способа входа очищает введённый секрет; при пересохранении профиля прежняя запись Keychain удаляется, новая создаётся только при включённом сохранении. Закрытые ключи и их пароль в профиль не копируются.

В **Сеть → Подключиться → SFTP → Способ входа SFTP → Пароль** нужен непустой пароль стандартной SSH password-аутентификации. Предел — 1023 байта UTF-8, без NUL и переводов строки. Он передаётся OpenSSH через одноразовый askpass и приватный FIFO, без записи секрета в аргументы, окружение или обычный временный файл. Неизвестный ключ сервера сначала требует подтверждения, изменённый отклоняется; до проверки ключа пароль серверу не отправляется. Ошибки парольного транспорта не показывают произвольный stderr сервера. Добавлены явный импорт основных параметров SSH config и цепочки до четырёх промежуточных серверов. У каждого — отдельный адрес/порт/пользователь/ключ и проверка host key; способ входа выбирается независимо для каждого узла: ключ/agent, пароль или keyboard-interactive/MFA. Запросы переходов не используют пароль конечного сервера. Импорт и изменение цепочки очищают введённый пароль. Правила, поддерживаемые директивы и ограничения — [SSH_CONNECTIONS.md](SSH_CONNECTIONS.md). Поддержаны несколько интерактивных вопросов и раундов, пароль + OTP и ключ + OTP. Ответы вводятся в отдельных окнах с адресом узла, не сохраняются, отмена и таймаут завершают запрос. Ограничения и повторные входы описаны в SSH_CONNECTIONS.md; полный язык config, включая ProxyCommand, пока не реализован.

## Проверки и оставшиеся работы

Проверка базового P10.3: 276 тестов в 30 наборах. В этот прогон входят 18 тестов движка и 7 сквозных тестов FTP/WebDAV; результаты интерфейса зафиксированы в журнале приёмки. SFTP проверяется реальным временным sshd на loopback с одноразовыми серверным/клиентским ключами, включая неизвестный/изменённый host key, операции, прогресс, отмену и таймаут. FTP/WebDAV имеют отдельные локальные тестовые серверы и проверки протокольных ответов/конфликтов. Общий движок проверяется независимо от UI. Эти проверки не заменяют UI-приёмку каждого протокола и испытания разных серверов; итоговый прогон и сценарии публикуются в [ACCEPTANCE.md](ACCEPTANCE.md).

После добавления парольного входа полный локальный прогон: **304 теста в 34 наборах**, сборка и 19 внутренних AppKit-проверок. Реальный системный OpenSSH проверен с изолированным SSH/SFTP-сервером: пароль с Unicode и спецсимволами, передача байтов, предельная длина, неверный пароль, отмена, таймаут и отказ неизвестному/изменённому ключу до передачи секрета. В интерфейсе проверены переключение способа входа, маскировка, очистка секрета при смене пользователя и отказ пустому паролю.

После SSH config/jump hosts: **332 теста в 36 наборах**, сборка и 24 внутренних AppKit-проверки прошли. Дополнительно вручную проверены импорт config и редактор переходов; реальная передача через два SSH-узла, отдельная проверка ключей и закрытие цепочки проверены протокольными тестами.

Открытый R16 сохраняет расширенную совместимость SSH config, дополнительные режимы конфликтов FAR и межсерверную передачу папок, безопасное удаление WebDAV-папок, полные сетевые метаданные, остатки поиска P4.4, WebDAV-аутентификацию кроме Basic и LOCK/UNLOCK. Там же остаются положительная проверка FTPS с доверенным сертификатом, межплатформенные/межсерверные испытания, прямой SMB, копирование между удалёнными панелями разных подключений и доказанное возобновление после перезапуска. Существующие R1–R15, включая архивный R15, остаются в плане без снятия ограничений.

После R16.3 (интерактивный SSH/MFA и парольные переходы): **355 тестов в 36 наборах**, сборка и **27 внутренних AppKit-проверок** прошли локально. Реальные сценарии включают два парольных перехода, несколько вопросов/раундов на каждом узле, ключ + OTP, отказ доверия, отмену/таймаут и отсутствие нового запроса при фоновой уборке. Выбор режимов вручную проверен в отдельной копии; CI этих изменений ещё не запускался.

## Расширенные операции R16.4

План `RemoteTreeOperations` строится только чтением и привязан к конкретному экземпляру провайдера и полному профилю подключения. Снимок включает все выбранные корни, вложенные записи и отсортированное содержимое каталогов; пути вне родителя, повторы, корень `/`, перекрывающиеся выделения и переход через символическую ссылку в предках отклоняются. Ссылки внутри дерева не раскрываются: при удалении удаляется сама ссылка. В окне видны число файлов/ссылок и папок, пути и отмена первой кнопкой; для больших планов явно показаны первые 1000 путей. Начало изменения требует отдельного подтверждения после завершения чтения. Перед первой командой проверяется весь снимок, перед каждой — текущий объект/предки, а перед удалением каталога — его пустота. Новые дочерние объекты сохраняются: FTP RMD и SFTP RMDIR обязаны отказать непустому каталогу даже при появлении файла после последнего чтения. Поэтому WebDAV-папки в этой команде отключены, включая пустые: предварительный PROPFIND не превращает DELETE в нерекурсивную команду.

Перенос в пределах одного и того же сохранённого SFTP/WebDAV-профиля использует серверное переименование, без промежуточной загрузки и удаления источника. Назначение должно отсутствовать; самоперенос, перенос в собственного потомка, конфликт файлов/папок и слияние отклоняются. SFTP использует стандартный RENAME без замены, WebDAV — MOVE с `Overwrite: F`. FTP/FTPS-перенос и переименование нового интерфейса отклоняются до изменения: RNTO не предоставляет атомарного запрета замены, и дополнительный stat этой гарантии не даёт. Старое поведение публикации подготовленной копии между локальной и FTP-панелями остаётся отдельно ограниченным указанным выше окном гонки.

Отмена проверяется при обходе, повторной проверке и перед каждой командой. Прогресс показывает текущий путь и число завершённых объектов. `RemoteMutationReport.completed` хранит точные подтверждённые сервером пути и назначения. При сбое `RemoteTreeOperationError` содержит этот отчёт, проблемный путь и признак неизвестного результата последнего запроса. Окно ошибки показывает число и первые 20 завершённых путей; полный список остаётся в отчёте API. Автоматического повторения, отката и удаления остатка нет. После потерянного ответа команда могла уже выполниться — прежде чем повторять, нужно обновить панели.

Снимки FTP/SFTP не являются серверной блокировкой или стабильными дескрипторами. Одновременная подмена объекта/предка другим клиентом между последним stat и командой и изменение байтов с прежними метаданными не исключаются. Нерекурсивное удаление защищает новое содержимое каталогов; оно не даёт общей транзакции или compare-and-swap для удаления обычных файлов. Полный паритет и промышленная приёмка всех серверов не заявлены. Слияние каталогов, перенос папок между локальной и сетевой панелью либо разными серверами, метаданные и прежние остальные R16 остаются в плане.
