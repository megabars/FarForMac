# Поиск: сверка FAR и исправление переносимости

Проверено 4 ноября 2026 года по FarGroup/FarManager, commit `1a6b02544b339615232078e0551463ef15b73ff9`, `far/findfile.cpp` (Git blob `328ff3a01549f352875ca92784e023fcc18cb3f6`).

## Что делает FAR

- `InitInFileSearch` задаёт [буфер 65 536 байт](https://github.com/FarGroup/FarManager/blob/1a6b02544b339615232078e0551463ef15b73ff9/far/findfile.cpp#L510).
- `LookForString` [проверяет остановку при чтении](https://github.com/FarGroup/FarManager/blob/1a6b02544b339615232078e0551463ef15b73ff9/far/findfile.cpp#L1041).
- Обычный текст ищется через [отдельный `m_TextSearcher->find_in`](https://github.com/FarGroup/FarManager/blob/1a6b02544b339615232078e0551463ef15b73ff9/far/findfile.cpp#L1185), без общего лимита 50 мс на файл в этом пути.
- [Обработка UTF-8 на границе буфера](https://github.com/FarGroup/FarManager/blob/1a6b02544b339615232078e0551463ef15b73ff9/far/findfile.cpp#L1247) и перекрытие блоков сохраняют совпадения, пересекающие границу чтения.

## Адаптация FarForMac

Поиск содержимого пока читает ограниченный по размеру UTF-8 файл целиком. Он сохраняет совпадения через границы чтения, но не повторяет потоковую архитектуру FAR и полный набор кодировок. Эти работы остаются в R8/P4.4.

До исправления буквальный текст и пользовательский regex проходили через один таймер 50 мс. На загруженном Intel корректный файл с Unicode мог попасть в пропущенные: в бюджет также входила подготовка UTF-16 диапазона и время ожидания процессора. В hosted CI `contentCrossesReadBlocksAndSnippetsRemainBounded` показывал один пропуск и отсутствие результата. Связь этого сбоя с бюджетом времени — вывод из кода и нагрузки прогона: прежний тест не печатал текст причины пропуска.

Теперь буквальный запрос экранирует все метасимволы и не получает таймер сложности regex. Сохраняются ограничения размера файла и запроса, проверки отмены при чтении и в обратных вызовах ICU. Пользовательские регулярные выражения по-прежнему имеют кооперативный бюджет 50 мс; подготовка диапазона выполняется до начала отсчёта. Это не жёсткий таймаут и не обещание одинакового с FAR диалекта или производительности.

Регрессии: совпадение на границе 64 КиБ, большой Unicode-текст, нечувствительность к регистру, буквальные regex-метасимволы, отсутствие совпадений, отмена и сохранение защиты от патологического regex. Результаты прогонов — в [ACCEPTANCE.md](ACCEPTANCE.md).
