# Правила проекта

## Память проекта

- Если разработчик поправил предложенный подход — предложи сохранить поправку правилом через скилл project-memory.

### Порядок разработки

- Сначала завершать все согласованные функциональные пункты spec.md, включая открытые P-пункты и реестр R; затем переходить к подготовке выпуска. Почему: базовое покрытие этапа не означает, что требуемые функции работают. (Не: переходить к релизу, оставив SSH-вход по паролю или другие функции в остатках.)
- Тесты и необходимые проверки безопасности выполнять вместе с каждой функцией. Не подменять ими функциональную разработку; незавершённые функции сохранять в плане и отчётах, не объявляя полный паритет FAR.
