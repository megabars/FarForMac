## Что делает официальный FAR

В [`FileList::CompareDir`, строки 4403–4530](https://github.com/FarGroup/FarManager/blob/1a6b02544b339615232078e0551463ef15b73ff9/far/filelist.cpp#L4403-L4530):

- Нужны две видимые файловые панели.
- Перед сравнением выбираются все объекты, кроме каталогов. Сравниваются непосредственные элементы панелей, без рекурсивного обхода.
- Имена сопоставляются без учёта регистра.
- Для совпавшего имени проверяются время последней записи и размер. При равном времени и разном размере пометка остаётся с обеих сторон. При более позднем времени помеченным остаётся новый файл; старый снимается с пометки. При совпадении времени и размера пометки снимаются с обеих сторон. Файлы без пары остаются помеченными.
- Для FAT или плагина с `OPIF_COMPAREFATTIME` используется специальная проверка времени. [`compare_fat_write_time`, строки 173–196](https://github.com/FarGroup/FarManager/blob/1a6b02544b339615232078e0551463ef15b73ff9/far/filelist.cpp#L173-L196) допускает совпадение после округления FAT до двух секунд или сравнения целых секунд. В остальных случаях время сравнивается непосредственно.
- Метод меняет пометки и обновляет отображение; копирование, удаление или синхронизацию он не выполняет. При отсутствии помеченных файлов выводится сообщение о совпадении.

## Реализация FarForMac

`DirectoryComparisonEngine` сравнивает обычные файлы непосредственно в двух локальных папках. Пометки соответствуют правилу FAR выше. По умолчанию имена сравниваются без учёта регистра; отдельный флаг включает точное сопоставление. Несколько имён, совпавших при выбранном сопоставлении, получают явный статус неоднозначности и исключаются из пометки и плана. Это важно для томов macOS с учётом регистра. Скрытые объекты можно исключить отдельно.

Время сравнивается точно с наносекундами из `stat`. FAT-округление и флаги плагинов не реализованы; текущий интерфейс сообщает о точном сравнении. Поддержка удалённых/архивных панелей не заявляется.

Дополнительный флаг включает побайтовую проверку обычных файлов одинакового размера, включая файлы с разным временем. Файлы разного размера уже считаются разными без чтения. Совпадение байтов не отменяет различие времени. При одинаковом времени и различающихся байтах помечаются обе стороны. При выключенном флаге интерфейс явно сообщает, что содержимое не проверялось.

Каталоги, символические ссылки и специальные файлы получают отдельные статусы пропуска. Их нельзя принять за подтверждённое совпадение. Вложенные каталоги не обходятся, цели ссылок среди дочерних объектов не открываются; конфликт типов получает отдельный статус. Явно выбранный корень разрешается через POSIX `realpath`, включая системные псевдонимы macOS `/var` и `/tmp`. Затем каждый компонент физического пути и все дочерние файлы открываются с `O_NOFOLLOW`. Повторная проверка снова разрешает исходный путь и отклоняет перенаправление корня к другому объекту. Пропуски и конфликты видны в таблице и в плане.

Работа выполняется вне главного потока; закрытие окна и Esc отменяют проверку. При отмене сохраняются уже полученные строки, а пометка и план отключены. По умолчанию пределы — 10 000 записей на каталог (включая скрытые записи при подсчёте предела), 64 МиБ на один файл и 512 МиБ суммарного чтения обеих сторон. Содержимое читается блоками по 64 КиБ, без загрузки файла целиком; память ограничена числом записей и двумя блоками. Ошибка чтения, превышение предела или изменение снимка делают сравнение неполным. Для неполного снимка API не выдаёт пометки, а все действия плана заблокированы.

Снимки проверяются по устройству, inode, типу/правам, размеру, времени изменения и ctime, включая наносекунды. До и после чтения проверяются открытые файлы; после сравнения и перед передачей пометок/показом плана заново открываются корни и проверяются корни и все прочитанные записи. Изменение состава каталога, замена файла и обычная запись с восстановленным mtime отклоняются. Как и любой снимок без блокировки внешних программ, результат может устареть после последней проверки. Пометки применяются только к панелям, сохранившим исходные пути.

## План синхронизации

План — расширение FarForMac, а не заявление о полном воспроизведении `CompareDir`. Пользователь выбирает направление слева направо или справа налево. Для источника без пары показывается копирование; для отличающейся пары — замена, с отдельным предупреждением, если источник старее назначения. Файл, присутствующий только в назначении, сохраняется; удаление не предлагается. Совпавшие файлы остаются на месте, каталоги/ссылки/специальные файлы/неоднозначности/конфликты пропускаются с объяснением.

Окно показывает полные пути источника и назначения для первых 1000 строк плана; при превышении этого предела выводится явное сообщение. Полный результат сравнения остаётся в таблице. Проверка актуальности и подготовка текста плана выполняются в фоне с отменой. Кнопки выполнения и API применения плана отсутствуют. Ни сравнение, ни пометки, ни предпросмотр не меняют содержимое или расположение файлов.

## Проверка

`DirectoryComparisonTests` проверяет правила пометки FAR, побайтовое различие при одинаковых метаданных, границу блока и пустые файлы, оба направления плана без записи, скрытые имена и регистр, поддержку явно выбранного корня через псевдоним и отказ при его перенаправлении, пропуск дочерних ссылок/циклов/FIFO/каталогов и конфликтов типов, ограничения чтения и перечисления, отмену и изменение снимка во время/после сравнения. Обычный путь `FileManager.temporaryDirectory` проверяет работу с системным псевдонимом `/var` без специальной подготовки пути тестом.

В окне доступны Cmd+Enter для запуска, Esc для отмены/закрытия, Cmd+M для пометки и Cmd+P для построения плана. Результаты представлены стандартной таблицей AppKit с выбором стрелками и полными сведениями выбранной строки; план доступен для выделения и копирования.
