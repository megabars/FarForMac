# Сетевые возможности FarForMac

Состояние на 30 октября 2026 года. Документ описывает реализованную базу этапа 10 и её границы; полный паритет FAR и полная UI-приёмка всех протоколов не заявлены. P10.3 включает проверенное продолжение обычного WebDAV-файла с сильным ETag в пределах текущего запуска; другие протоколы безопасно перезапускают передачу. Основной план — [spec.md](../spec.md), сопоставление с FAR — [NETWORK_REFERENCE.md](NETWORK_REFERENCE.md), фактические результаты проверок — [ACCEPTANCE.md](ACCEPTANCE.md).

## Протоколы и подключения

| Возможность | SFTP | FTP / явный FTPS | WebDAV HTTP / HTTPS |
| --- | --- | --- | --- |
| Транспорт | Системный OpenSSH, бинарный SFTP v3; удалённый shell не используется | Системная libcurl; MLSD вместо разбора человекочитаемого LIST | URLSession, PROPFIND и операции WebDAV |
| Аутентификация | Закрытый ключ / SSH agent; пароль ключа может получать OpenSSH из macOS Keychain | Пользователь и пароль | Basic auth |
| Проверка сервера | Отдельный known_hosts приложения; новый отпечаток подтверждается явно, изменённый ключ отклоняется | FTPS проверяет сертификат и имя сервера, защищает управляющее соединение и данные | HTTPS проверяет сертификат и имя сервера |
| Открытая передача | Нет | FTP требует предупреждения перед подключением | HTTP требует предупреждения перед подключением |
| Список / сведения / навигация | Да | Да; сервер должен поддерживать MLSD | Да; PROPFIND Depth 0/1 |
| Файлы: скачать / отправить / переименовать | Да | Да, в пределах серверного RNFR/RNTO | Да, GET / PUT / MOVE |
| Папка / удаление файла или пустой папки | Да | Да | Да; приложение не использует DELETE для автоматического удаления непустого дерева |
| Условное сохранение существующего файла | Проверка снимка и байтов; атомарного compare-and-swap нет | Проверка снимка и байтов; атомарного compare-and-swap нет | Сильный ETag: PUT с If-Match; без него — проверка снимка/байтов и MOVE |

FTPS означает явный TLS на FTP-порту, а не отдельный неявный FTPS-протокол. Нельзя молча принять неизвестный сертификат либо отключить проверку имени. Положительный сквозной FTPS-сценарий с реально доверенным сертификатом остаётся отдельной проверкой R16; проверка отказа недоверенному сертификату его не заменяет.

SMB доступен через уже смонтированный macOS-том или папку в обычной файловой панели. Прямой SMB-провайдер, обнаружение серверов и управление монтированием не реализованы.

## Команды панели и рабочие копии

Меню **Сеть** создаёт подключение, отключает панель, открывает удалённый путь, обновляет/подключается повторно и отменяет работу. Команды **Продолжить скачивание** и **Сбросить незавершённое скачивание** явно повторяют удерживаемое задание или удаляют его приватную частичную копию. Повтор относится к обычным файлам, скопированным с сетевой панели в локальную; отправка, перенос и папки используют новую операцию. В сетевой панели Enter открывает папку или просмотр файла, Tab переключает панель, Esc отключает; курсор и пометки определяют выбранные объекты.

| Команда | Реализованное поведение | Граница |
| --- | --- | --- |
| F3 | Полная загрузка в приватную копию, затем существующий постраничный просмотрщик | Прямого чтения блоков с сервера нет; на локальном диске нужно место для полного файла |
| F4 | Полная загрузка в приватную копию и редактор | Предел редактора 8 МиБ; сохранение редактора меняет только копию |
| «Сохранить на сервер» | Отдельная отправка сохранённой копии после повторной проверки версии и SHA-256 исходного серверного содержимого | Конфликт сохраняет локальные правки; автоматического слияния нет |
| F5 | Копирование между обычной и сетевой панелями; файлы и ограниченные деревья папок | Папка требует нового назначения; слияния нет; две удалённые панели не поддержаны |
| F6 | Перенос обычного файла после публикации, чтения и проверки копии и повторной проверки источника | Перенос папок отклоняется; ошибка удаления источника оставляет проверенную копию |
| F7 | Создать удалённую папку | Одна команда, без слияния существующих папок |
| F8 | Удалить выбранный файл или пустую папку после подтверждения | Без Корзины и undo; автоматического рекурсивного удаления нет |

Переход F6 из сетевого просмотрщика в редактор сохраняет позицию и кодировку рабочей копии. Обратный F6 из сетевого редактора с сохранением связи с сервером остаётся R16/P5.4. Окно отправки удерживает локальную копию после закрытия редактора; её можно отправить отдельно. Приватные рабочие файлы удаляются при завершении сеанса/последней ссылки и штатном завершении приложения. Восстановление рабочих копий после аварийного завершения не обещается.

## Целостность и ограничения операций

Копия публикуется после проверки подготовленных данных. Для переноса источник удаляется после чтения и проверки назначения. Публикация не использует удаление старого назначения как обход отказа rename. Если безопасная для выбранного сценария замена не поддержана сервером, операция сообщает ошибку. При независимой записи другим клиентом FTP/SFTP и WebDAV без сильного ETag сохраняют окно гонки между последней проверкой и rename/удалением; полной транзакционности нет.

Сильный ETag WebDAV используется как серверное условие If-Match при записи. Ответ 412 означает конфликт; локальные изменения остаются доступны. Потеря ответа после публикации может означать уже выполненную запись: перед повтором необходимо проверить текущее состояние сервера. Завершённые файлы при отмене не откатываются.

Копирование дерева ограничено 128 уровнями вложенности, 100000 объектов и 1 ТиБ на выбранное дерево. Дочерние пути и повторяющиеся имена проверяются; символические ссылки и специальные файлы не копируются. Сетевые POSIX-права, владельцы, исходные даты, ACL, xattr и resource forks не переносятся. Рабочие копии используют приватные права 0600/0700, что не означает сохранения метаданных источника.

После прерванной серверной подготовки может остаться `.farmac-upload-UUID`. Общий движок не удаляет такой объект без доказательства владения; приложение не обещает общего отката. SFTP-провайдер отдельно пытается очистить собственный исключительно созданный временный файл при отмене/ошибке. Наличие локального либо удалённого `.part` само по себе не разрешает продолжение передачи.

## Прогресс, повтор и секреты

Фоновые сетевые операции показывают байтовый прогресс, поддерживают отмену и таймаут. Повторное подключение выполняется обновлением панели. Сетевые задания используют собственное окно операции, а не постоянный журнал локальной очереди.

Ядро P10.3 удерживает только собственный приватный частичный файл в пределах текущего запуска. Для WebDAV с сильным ETag первый GET условный (`If-Match`); перед продолжением заново проверяются все параметры подключения, серверный снимок/ETag, идентичность локального файла, размер, времена изменения и SHA-256 всего полученного префикса. Только после этого отправляются Range и If-Match; изменение версии или подмена префикса требуют новой операции. Перед публикацией проверяются полный размер, свежий серверный снимок и исходный снимок локального назначения. Этот контракт прошёл 18 детерминированных тестов ядра и сквозные проверки прерванного HTTP. Если отмена не позволила закончить проверку префикса, повтор начинает передачу с нуля. После ошибки задание удерживается до явного повтора, сброса или штатного завершения приложения; успешно завершённые объекты повторно не передаются. Слабый ETag, FTP и SFTP безопасно начинают передачу с нуля. Продолжение произвольного `.part`, после перезапуска приложения и без сильного ETag не заявлено.

Профили `~/Library/Application Support/FarForMac/Connections.json` содержат адрес, протокол, имя пользователя, путь, порт, таймаут и путь к SSH-ключу; пароли в JSON не записываются. Пароль FTP/WebDAV сохраняется в macOS Keychain только при явном выборе пользователя вместе с сохранением параметров подключения. SFTP не принимает пароль входа; закрытые ключи и их пароль не копируются в профиль. Пользовательский SSH config, ProxyCommand и jump hosts не подключаются автоматически.

## Проверки и оставшиеся работы

Итоговая общая проверка, включая P10.3: 276 тестов в 30 наборах. В этот прогон входят 18 тестов движка и 7 сквозных тестов FTP/WebDAV; результаты интерфейса зафиксированы в журнале приёмки. SFTP проверяется реальным временным sshd на loopback с одноразовыми серверным/клиентским ключами, включая неизвестный/изменённый host key, операции, прогресс, отмену и таймаут. FTP/WebDAV имеют отдельные локальные тестовые серверы и проверки протокольных ответов/конфликтов. Общий движок проверяется независимо от UI. Эти проверки не заменяют UI-приёмку каждого протокола и испытания разных серверов; итоговый прогон и сценарии публикуются в [ACCEPTANCE.md](ACCEPTANCE.md).

Открытый R16 сохраняет парольную аутентификацию SFTP, SSH config/jump hosts, перенос/слияние папок, рекурсивное удаление, полные сетевые метаданные, поиск P4.4, обратный F6/P5.4, WebDAV-аутентификацию кроме Basic и LOCK/UNLOCK. Там же остаются положительная проверка FTPS с доверенным сертификатом, межплатформенные/межсерверные испытания, прямой SMB, две удалённые панели и доказанное возобновление после перезапуска. Существующие R1–R15, включая архивный R15, остаются в плане без снятия ограничений.
