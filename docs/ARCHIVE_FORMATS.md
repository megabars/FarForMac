# Архивы: форматы, библиотека и ограничения

Реализация использует системную `libarchive` macOS через C API. На проверенной
машине `archive_version_string()` возвращает `libarchive 3.7.4`, номер версии —
`3007004`. Это версия динамической библиотеки текущей ОС: другая версия macOS
может поставлять другую версию библиотеки. Приложение не запускает внешние
архиваторы. Публичные заголовки взяты из официального выпуска libarchive 3.7.4;
исходный код библиотеки в проект не включён.

| Формат | Список и чтение | Создание и изменение | Пароль |
| --- | --- | --- | --- |
| Обычный ZIP | Да | Да | Незашифрованные архивы |
| ZIP с ZipCrypto | Да | Нет | Извлечение с паролем через C API |
| ZIP с WinZip AES-256 | Да | Нет | Извлечение с паролем через C API |
| Несжатый TAR | Да | Да | Не применяется |
| TAR.GZ, TAR.BZ2, TAR.XZ | Да | Да, с сохранением вида сжатия | Не применяется |
| ZIP64 в пределах лимитов | Да | Изменение с возможной записью обычного ZIP; принудительное создание ZIP64 не заявлено | Как для ZIP |
| Остальные внешние фильтры TAR | Нет | Нет | Не применяется |
| Многотомный и самораспаковывающийся ZIP | Нет | Нет | Не поддерживается |
| 7z, RAR и остальные форматы libarchive | Нет | Нет | Не поддерживается |

Возможности намеренно ограничены этой таблицей, даже если системная библиотека
умеет больше. AES-256 и ZipCrypto проверяются тестами на небольших зашифрованных
ZIP, создаваемых через библиотечный API. Другие схемы шифрования и пароли для
создания архивов не заявлены. Заголовки обычного ZIP доступны без пароля; проверка
пароля, CRC и целостности содержимого выполняется при извлечении. Успешное
открытие списка само по себе не означает успешную проверку всех данных.

Для незашифрованных ZIP/ZIP64 и поддержанных TAR изменение включает F7 (явные пустые
каталоги), внутренний F6 (переименование/перемещение выбранных деревьев в одной
транзакции), добавление, удаление и применение редакторской копии. Новые родители
могут быть неявными. Внутренний F6 отказывает при конфликте иерархии или имени,
не сливает и не заменяет существующее назначение. Каждая операция сохраняет
исходный контейнер до полного повторного извлечения и сравнения байтов нового;
изменённый извне снимок и отмена до публикации дают отказ без изменения архива.
Для шифрованных ZIP F7/F6 также запрещены. Передача между двумя архивами,
ссылки, полная верность всех метаданных и остальных режимов ArcLite остаются
за границами этой таблицы; детали — [ARCHIVE_WRITE_REFERENCE.md](ARCHIVE_WRITE_REFERENCE.md).

## Проверенные расширения R15.2

`ArchiveFormatsTests` создаёт независимые небольшие фикстуры через C API для
TAR+gzip/bzip2/xz и принудительный ZIP64 (`zip:zip64=1`), затем проверяет наше
ядро. Для каждого сжатого TAR проверены сигнатура выходных байтов, чтение,
создание, F7, внутренний F6, добавление, точная замена, удаление и пустой архив.
После изменения сохраняется вид фильтра, а не прежний уровень сжатия или
побайтовое представление контейнера. Новое содержимое полностью извлекается и
сравнивается с источниками до публикации. Проверены отказ опасных путей,
лимиты распаковки, отмена, изменение источника и отсутствие оставшихся файлов
стадии. Вложенные фильтры и сжатый снаружи ZIP отклоняются.

Включаются только `none`, `gzip`, `bzip2`, `xz` и только при `ARCHIVE_OK`
от каждого отдельного вызова регистрации. `ARCHIVE_WARN` не принимается:
libarchive может так предлагать запуск внешнего архиватора. Внешние программы
не запускаются. Версия или наличие libarchive сами по себе не являются
доказательством поддержки формата. На другой поставке ОС отсутствие встроенного
фильтра приводит к явному отказу; подмена фильтра или внешняя программа не
используется.

Для TAR.XZ проверен ограниченный вариант: один XZ stream, один блок LZMA2,
без дополнительных фильтров, словарь не больше 64 МиБ и несжатый поток TAR
не больше 2 ГиБ (включая служебные заголовки/заполнение; файловые лимиты ниже
продолжают действовать). Предварительно проверяются CRC служебных структур,
индекс, границы блока, свойства словаря и рамки порций LZMA2 без декодирования
их данных. Это нужно до вызова декодера: upstream libarchive 3.7.4 не задаёт
лимит памяти LZMA. Проверены отказ корректного свойства словаря 4 ГиБ,
нескольких stream, цепочки фильтров и преждевременного окончания блока.
Многоблочный/конкатенированный XZ и BCJ/Delta остаются вне поддержанного варианта.
Выбирается ровно один внешний фильтр по сигнатуре, автоматическое повторное
распознавание отключено, чтобы вложенный XZ не мог обойти эту проверку.
Это ограничение словаря и потока, а не общий жёсткий предел памяти процесса.

ZIP64 проверен на небольшом архиве с 64-битным каталогом и размерами. До чтения
проверяются EOCD/locator, число томов, размер и границы каталога, 64-битные поля
элементов, локальные заголовки и совпадение имён. Переполнение, неполные поля и
многотомность отклоняются. Это не обещание обработки многогигабайтных файлов:
обычные лимиты ниже продолжают действовать. Пересборка небольшого ZIP64 может
дать обычный ZIP; сохранение самого расширения ZIP64 не является контрактом.

Вложенные поддержанные архивы открываются отдельно через Enter для известного
расширения либо явную команду открытия архива. Родительская строка, Backspace
и Esc возвращают родительскую архивную панель с прежними каталогом, курсором и
пометками. Вложенная панель помечается как доступная только для чтения:
просмотр, извлечение и поиск разрешены; редактор, добавление, удаление, F6/F7 и
применение редакторской копии запрещены. Обратная запись временного контейнера
в родителя не выполняется. Для изменения нужно извлечь архив в обычный файл.

`ArchiveNavigationFrame` удерживает цепочку родителей, а сам снимок вложенного
архива удерживает свою приватную рабочую папку и версии всех предков. Поэтому
просмотр/поиск может пережить выход из панели; папка удаляется после последнего
потребителя. Изменение любого предка требует открыть цепочку заново. Максимум —
4 вложенных уровня и 256 МиБ суммарного размера удерживаемых файлов-контейнеров,
дополнительно ограниченного `maximumTotalBytes` исходного снимка. Каждый уровень
отдельно проходит обычные лимиты распаковки; это не общий лимит памяти всех
одновременно открытых окон. Повторная упаковка снимка в навигационный объект не
сбрасывает глубину и бюджет. Внешний и внутренний зашифрованные ZIP могут иметь
разные пароли; пароли не сохраняются в кадре или снимке.

## Лимиты чтения и извлечения

Значения `ArchiveLimits.default`:

| Ограничение | Значение |
| --- | --- |
| Число заголовков элементов | 10 000 |
| Размер одного обычного файла | 256 МиБ |
| Общий распакованный размер файлов | 1 ГиБ |
| Общий размер / размер исходного архива | Не больше 1 000 |
| Глубина пути | 128 компонентов |
| Длина пути | 16 384 байта UTF-8 |
| Длина компонента пути | 255 байт UTF-8 |

Список проверяет заявленные размеры и все пути. Извлечение дополнительно считает
фактически прочитанные байты порциями по 64 КиБ, проверяет размер каждого файла и
целостность данных. Сумма размеров и коэффициент распаковки проверяются без
переполнения целых чисел. Лимиты можно задать через программный API; настройки
интерфейса для их изменения не предусмотрены.

Все имена проверяются до создания рабочей папки, включая элементы вне выбранной
части архива. Отклоняются абсолютные пути, `..`, внутренние `.` и пустые
компоненты, обратная косая черта, двоеточие и NUL. Начальное `./` и завершающий
слеш каталога нормализуются. Имена приводятся к NFC; повторные имена, коллизии
регистра и Unicode, а также конфликт «файл является родителем другого элемента»
отклоняются. Исходные имена ZIP дополнительно проверяются до нормализации внутри
библиотеки. Символьные и жёсткие ссылки, устройства, FIFO и другие специальные
элементы не извлекаются: архив с такими элементами отклоняется целиком.

Извлечение создаёт только новую приватную временную папку приложения с правами
`0700`; обычные рабочие файлы имеют права `0600`. Папки и файлы открываются через
дескриптор родителя, с запретом следовать символьным ссылкам и с исключительным
созданием файлов. Произвольный внешний каталог назначения не принимается этим
API. Дальнейшее копирование в пользовательское назначение выполняет обычный
механизм файловых операций с разрешением конфликтов.

Пароль передаётся библиотеке в памяти, не включается в командную строку, журналы,
настройки или снимок архива. Рабочие копии содержат открытый текст: они существуют
до закрытия использующего их окна либо завершения операции, затем удаляются.
Удаление временного файла не является гарантированным физическим стиранием
данных с накопителя. Архив повторно проверяется по устройству, inode, размеру и
времени изменения/метаданных перед операцией и после чтения; изменение источника
требует открыть его заново. Отмена кооперативная между заголовками и порциями
данных. Жёсткое прерывание заблокированного системного ввода-вывода не обещается.

### AppleDouble при чтении

Автоматическая обработка macOS-метаданных libarchive отключена для TAR и ZIP. `._*` и `__MACOSX` читаются как обычные элементы с проверкой размеров; скрытые имена в поиске подчиняются настройке скрытых файлов. Восстановление этих членов как resource forks/xattr не реализовано. Поиск и ограничения нативного парсера описаны в [ARCHIVE_SEARCH_REFERENCE.md](ARCHIVE_SEARCH_REFERENCE.md).
