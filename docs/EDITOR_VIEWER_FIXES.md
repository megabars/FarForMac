# Повторная сверка редактора и просмотрщика

Эталон — Far Manager 3.0 build 6747 (`1a6b02544b339615232078e0551463ef15b73ff9`). Идентификаторы относятся к [аудиту редактора и просмотрщика](audit/EDITOR_VIEWER.md).

| V03–V04 | Shift+F4 открывает список режимов. Повторный выбор активного режима сохраняет базовый режим. В тексте Shift+F2 переключает перенос по словам и символам. В режиме без переноса Left/Right сдвигают область на одну колонку, Ctrl+Left/Right — на 20. Alt+←/→ меняет ширину строки на один байт, Ctrl+Alt+←/→ переходит к соседнему кратному 16 с учётом доступной ширины. Именованный новый буфер создаёт файл по F2 с эксклюзивной записью. Для новых именованных файлов выбраны CRLF, ANSI по умолчанию и BOM при явном Unicode. ## Остатки

- Просмотрщик. Полоса F-клавиш и локальные настройки, автоопределение двоичного режима, совместимость SearchWrapStop и движка regex, непрерывное выделение и прокрутка мышью через границы блоков, полная история переходов и выбора режима, быстрый просмотр и контекстные плагины. Горизонтальная колонка соответствует ширине моноширинного символа AppKit, а край прокрутки определяется шириной загруженного блока. Для управляющих символов hex и дамп используют инертные видимые знаки. Ширина широких глифов зависит от шрифта. При выделении нескольких строк hex AppKit включает между крайними байтами текст и адреса промежуточных строк.
- Редактор. Контекстная полоса F-клавиш и выбор внешнего редактора, полная механика вертикального и постоянного блоков, виртуальный курсор, сессионные закладки и восстановление экрана при Undo, полный набор команд меню результатов, локальные параметры поиска и формата, предупреждение размера с продолжением, управление режимом только чтения и совпадение интерфейса внешнего конфликта. Повторное открытие, переключение экранов и передача списка соседей требуют отдельной приёмки.
- Общие сценарии. Избранные, переименование, скрытие разделов и настраиваемый цикл F8 в меню кодовых страниц, режимы публикации плагинов FAR, общая история и полный контекст макросов. Для грязного буфера с непредставимыми данными редактор отказывает в преобразовании; сценарий FAR с подтверждением потерь открыт. Для обеих платформ нужны физические проверки Fn, Right Ctrl, IME и VoiceOver.

Модульные проверки покрывают синтаксис Go To, двунаправленную массовую замену, обратимость DOS-кодировок, байтовую карту hex, декодирование на границах строк и шаги изменения ширины. AppKit smoke проверяет End и начало слежения, клавиатуру закладок, Shift+F2, размеры строк дампа и hex, отсутствие временных снимков в истории и запись названного буфера с BOM/CRLF. Сопоставление с запущенным Windows FAR остаётся открытым.
