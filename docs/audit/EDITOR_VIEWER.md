# Просмотрщик и редактор FarForMac

Эталон — Far Manager 3.0, build 6747, commit `1a6b02544b339615232078e0551463ef15b73ff9` из `spec.md`. Официальные исходники и справка для этого commit прочитаны через GitHub. Колонка FarForMac относится к текущему рабочему дереву. Сценарии в последней колонке предназначены для воспроизведения на обеих платформах. Итоги основаны на чтении кода. Для этого среза не запускались Windows FAR, FarForMac, сборка или тесты. Предыдущие проверки из [журнала приёмки](../ACCEPTANCE.md) подтверждают отдельные сценарии FarForMac.

**Статусы** — «совпадает» относится только к описанному действию в коде, «частично» означает общий результат в более узкой области, «отличается» — другой интерфейс, назначение или результат, «нет» — отсутствующий пользовательский путь, «не проверено» — недостающая проверка среды или недостаточные данные для вывода. Дополнения FarForMac и ограничения платформы вынесены отдельно. Диапазоны строк относятся к снимку на дату аудита.

### Границы сравнения

- Windows FAR открывает просматриваемый файл с разрешением отложенного удаления. На macOS удаление имени и доступ по открытому дескриптору имеют POSIX-семантику. Проверяемое поведение FarForMac — снимок обычного файла и повторная проверка идентичности, выдающая ошибку при изменении пути или данных. Отдельно нужны прогоны с удалением/заменой файла, заблокированным доступом и чтением на сетевом томе. [Справка FAR:2923–2929](https://github.com/FarGroup/FarManager/blob/1a6b02544b339615232078e0551463ef15b73ff9/far/FarEng.hlf.m4#L2923-L2929), [FileViewer.swift:47–127](../../Sources/FarCore/FileViewer.swift#L47-L127).
- Windows FoldString, системные ANSI/OEM-коды, консольные глифы и двоичные плагины FAR используют API Windows. На macOS различаются таблицы Unicode, отображение управляющих символов и ширина глифов. Полный каталог поддерживаемых кодировок, назначение F8/Shift+F8, контекстные меню и режимы работы с блоками остаются самостоятельными переносимыми функциями. [Справка FAR:3597–3634](https://github.com/FarGroup/FarManager/blob/1a6b02544b339615232078e0551463ef15b73ff9/far/FarEng.hlf.m4#L3597-L3634), [SearchTextFolding.swift](../../Sources/FarCore/SearchTextFolding.swift), [FileViewer.swift:267–327](../../Sources/FarCore/FileViewer.swift#L267-L327).
- Физический Fn, клавиши numpad, левый/правый Ctrl, IME, RU/EN, VoiceOver, чтение и состояние при переключении нескольких окон требуют реальных прогонов. Текущие источники доказывают, какие ветки зарегистрированы, а порядок доставки события глобальному и локальному обработчикам и доступность контролов при фокусе остаются непроверенными. [ViewerWindow.swift:811–879](../../Sources/FarForMac/ViewerWindow.swift#L811-L879), [TextFileWindow.swift:213–224](../../Sources/FarForMac/TextFileWindow.swift#L213-L224), [App.swift:202–217](../../Sources/FarForMac/App.swift#L202-L217), [ACCESSIBILITY.md](../ACCESSIBILITY.md).
- Отдельный флажок слежения, постоянно видимые поля поиска и перехода, числовой прямоугольник, отдельное окно публикации и рабочий процесс внешнего конфликта — решения FarForMac. Для их отличия от FAR не выявлено технической неизбежности на macOS. Надёжность записи и отказ от потерянного декодирования оцениваются независимо от совпадения интерфейса. [VIEWER_REFERENCE.md](../VIEWER_REFERENCE.md), [EDITOR_REFERENCE.md](../EDITOR_REFERENCE.md).
