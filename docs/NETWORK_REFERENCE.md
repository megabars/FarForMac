# Сеть: сверка с исходниками FAR и границы переноса

Проверено 30.10.2026 по официальному FarGroup/FarManager, commit `1a6b02544b339615232078e0551463ef15b73ff9`. Прочитаны реальные исходники `plugins/ftp/AskOver.cpp`, `cnDownload.cpp`, `cnUpload.cpp` и `DeleteFile.cpp` через GitHub. Код Windows-плагина FAR в сборку FarForMac не включён. SFTP и WebDAV — собственные поставщики FarForMac; наличие этих протоколов в штатном FTP-плагине FAR не заявляется.

Копирование папок рекурсивное, с пределами 128 уровней вложенности, 100000 объектов и 1 ТиБ на выбранное дерево, проверкой дочерних путей и отказом от символических ссылок. Загрузка папки на сервер требует отсутствующего назначения; замена и слияние сетевых папок не реализованы. Скачивание поверх локальной папки также требует другого имени. Метаданные UNIX, ACL, xattrs и исходные временные метки через сеть не сохраняются. Каждое имя из листинга должно быть непосредственным дочерним путём; `..`, повторяющиеся имена и выход из каталога отклоняются.

Перемещение реализовано для обычных файлов: исходник удаляется только после публикации, чтения байтов назначения и повторной проверки исходника. Если проверка/очистка не удалась, опубликованная копия и исходник сохраняются в доступном состоянии; повторное действие пользователя требует обновления панели. Перемещение папок отклоняется до записи: доступны копирование и отдельное явное удаление.

Просмотр и редактирование используют `RemoteWorkspace`. Открытый файл получает снимок `RemoteEntry` и SHA-256 полного содержимого. Сохранение фиксирует отдельную локальную копию правок, сравнивает метаданные и все текущие серверные байты с исходным снимком и лишь после этого публикует новую версию. Проверка обнаруживает также изменение содержимого с прежними размером и mtime. Конфликт сохраняет локальные правки; успешное сохранение возвращает новый снимок для следующего сохранения. При закрытии последней ссылки приватный каталог удаляется; приложение также вызывает `cleanup()` при штатном завершении. Восстановление после аварийного завершения и автоматическая очистка оставшихся сетевых рабочих каталогов не обещаются.

FTP/FTPS и обычный SFTP не предоставляют этому интерфейсу compare-and-swap: между последней проверкой и rename либо удалением другой клиент может изменить объект. Поэтому полная атомарность при независимой конкурентной записи не заявляется. Реализация не удаляет существующий файл для обхода отказа rename. Если сервер не поддерживает требуемую замену, операция завершается ошибкой, сохраняя старое назначение и подготовленную копию. При ошибке передачи может остаться соседний `.farmac-upload-UUID`: автоматическое удаление такого объекта без серверного доказательства владения не выполняется.

Для WebDAV с сильным ETag обновление существующего обычного файла использует условный HTTP PUT `If-Match`. Серверный ответ 412 оставляет конфликт на разрешение пользователю. Слабый ETag не считается доказательством неизменности; для него остаются сравнение байтов и проверенный MOVE с описанным окном гонки. WebDAV без ETag, FTP и SFTP не получают вымышленной гарантии CAS. Потеря ответа или отмена после публикации может означать, что новая версия уже записана: перед повтором требуется обновление панели.

`RemoteDownloadTask` реализует возобновление обычного файла WebDAV в пределах открытого приложения. Первая попытка использует условный GET `If-Match` с сильным ETag; повторная — дополнительно `Range`. Частичная копия создана исключительно в приватном рабочем каталоге задачи, а после сбоя фиксируются её inode, размер, времена изменения и SHA-256 всех записанных байтов. Перед повтором проверяются полный профиль сервера, точное совпадение `RemoteEntry` с сильным ETag, локальная идентичность и SHA-256 префикса. Подмена/изменение частичной копии или новая версия сервера запрещают продолжение: требуется явное удаление сохранённой задачи и новая загрузка. Ответ 412, неверный диапазон, игнорирование Range ответом 200 и несовпадающий ETag не дописываются к частичной копии. После получения полного размера свежие серверные свойства проверяются снова; локальное назначение сравнивается со снимком, сделанным при создании задачи, и публикуется через локальный движок.

Задача сохраняет приватную копию только пока удерживается приложением; `cleanup()` отменяет активный запрос, ждёт его завершения и удаляет рабочий каталог. Автоматическое продолжение после перезапуска приложения, принятие чужих `.part`, возобновление папок или перемещения не поддерживаются. Для FTP/FTPS/SFTP и WebDAV со слабым/отсутствующим ETag повтор всегда скачивает файл с нулевого смещения. Предел размера — 1 ТиБ; вычисление SHA-256 потоковое, без загрузки всего файла в память.

SFTP, FTP и WebDAV проверены на локальных серверах и через интерфейс; отказ недоверенным HTTPS/FTPS-сертификатам проверен автоматически. Положительный FTPS-сценарий с доверенным сертификатом и матрица других серверов остаются отдельной приёмкой; точные результаты — в ACCEPTANCE.md.
