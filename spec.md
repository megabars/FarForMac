# FarForMac: план развития до функционального аналога Far Manager

Дата обновления: 4 ноября 2026 года. Статус: реализованы базовые этапы 1–11 в описанных ниже границах, включая безопасное продолжение скачивания обычных WebDAV-файлов с сильным ETag в текущем запуске приложения. P5.4 выполнен для локальных файлов и временной панели; архивные и сетевые файлы материализуются в приватные рабочие копии, просмотр → редактор поддержан, обратный F6 из этих редакторов остаётся открытым. Аппаратные проверки P3.4, поиск внутри архивов/сети P4.4 и полный паритет FAR не закрыты. Макросы и API расширений реализованы в границах P11.1–P11.5, остатки сохранены в R17; следующий этап — 12, качество и выпуск. Приёмка каждого этапа фиксируется отдельно.

## 1. Цель и границы

Создать самостоятельное нативное приложение macOS с двумя панелями, управлением с клавиатуры и основными сценариями реального Far Manager: работа с файлами, архивами и удалёнными ресурсами, просмотр и редактирование, поиск, командная строка, пользовательские команды и расширения.

Сохраняем поведение FAR там, где оно не зависит от Windows. Внешний вид, системные диалоги, доступность, Корзина, разрешения и интеграция с Finder/Terminal адаптируются к macOS. Отличия документируем, а не обозначаем как полную совместимость.

«Готово» означает реализованный и проверенный сценарий с критериями ниже. Две панели, схожие кнопки или наличие метода без проверки не означают завершение возможности. Совместимость со всеми сторонними плагинами FAR и загрузка Windows DLL не входят в обещание первой полной версии; для расширений предусмотрен отдельный этап и собственный контракт.

## 3. Исходное состояние

Реализованы две локальные панели, навигация, сортировка имени/размера/даты, фильтр по подстроке, скрытые файлы, копирование/перемещение без перезаписи, переименование, новая папка, Корзина, UTF-8 просмотрщик/редактор до 8 МиБ, открытие Finder/Terminal и сохранение путей панелей.

Исходные ограничения: выбор NSTableView вместо пометок FAR; F2 открывает фиксированные действия; нет полноценного F6 с новым именем назначения, прогресса и отмены операций, архивов, сети, встроенного терминала, рекурсивного поиска, макросов и плагинов. Начальные 19 тестов проверяют файловое ядро. Подробности — [аудит совместимости](docs/FAR_PARITY.md).

## 4. Архитектурные правила

1. `FarCore` содержит модели, маски, планирование операций и провайдеры без AppKit. `FarForMac` отображает состояние и передаёт команды; бизнес-правила тестируются отдельно.
2. Курсор, пометки, фильтр и список элементов — отдельные состояния. Файловая операция получает неизменяемый список источников и назначения при подтверждении.
3. Провайдеры локальной файловой системы, архивов и сети реализуют явные возможности: чтение, запись, перенос, метаданные, ссылки, прогресс, отмена. Неподдерживаемая возможность отключается с понятной причиной.
4. Длительные операции не блокируют главный поток. Операции публикуют прогресс и частичные результаты; отмена не обещает откат завершённых действий.
5. Строки имён и пользовательские пути не вставляются без экранирования в shell. Для файловых операций shell не используется. Команды пользователя исполняются только после явного запуска в интерфейсе.
6. Состояние панели сохраняется по идентичности элемента, а не индексу строки. После обновления не допускается применение старого выделения к новому файлу на той же строке.
7. Чужой код не переносится без записи источника и лицензии. Наличие BSD-3-Clause у FAR не заменяет проверку лицензий отдельных компонентов; у far2l и зависимостей свои условия.

### Этап 1. Курсор, пометки и маски — реализован

Это первый приоритет: от корректного списка целей зависят все последующие операции.

- [x] **P1.1** Отделить курсор от пометок. Обычное движение курсора не снимает пометки; `..` не помечается и не попадает в операции.
- [x] **P1.2** Insert переключает пометку текущего объекта и сдвигает курсор вниз. Shift+↑/↓ применяет состояние, выбранное в начале удержания Shift, к покидаемой строке. Отпускание Shift завершает жест.
- [x] **P1.3** Gray +/− выделяет/снимает по маске, Gray * инвертирует пометки файлов; Ctrl+Gray * включает папки. По умолчанию массовая пометка не добавляет папки, но может снимать их пометки. Cmd+A явно помечает все видимые объекты как macOS-команда.
- [x] **P1.4** Реализовать начальный синтаксис масок: `*`, `?`, классы символов, несколько масок через `,`/`;`, исключение через `|`, совместимое значение `*.*`. Ошибочная или неподдерживаемая маска не изменяет выделение.
- [x] **P1.5** F5/F6/F8 применяются к пометкам; без пометок — к объекту под курсором. F3/F4 открывают файл под курсором независимо от пометок. Shift+F6 переименовывает объект под курсором независимо от пометок.
- [x] **P1.6** Сохранить курсор и пометки при сортировке/обновлении; при переходе в другую папку очистить. При скрытии элементов фильтром снять их пометки — явное правило FarForMac, чтобы невидимые файлы не участвовали в операции.
- [x] **P1.7** Показать маркеры, количество и суммарный размер помеченных файлов; добавить меню и подсказки для клавиатуры без Insert/numpad.

Приёмка: пометить A и B, перейти курсором на C, выполнить F5 — копируются A и B. При тех же пометках F3 открывает C, Shift+F6 меняет только C. Сортировка не меняет набор. После фильтра не возникает скрытых целей. `*.swift;*.md|README*` выбирает ожидаемый набор. Папка и `..` обрабатываются согласно правилам, пустая панель не вызывает ошибку.

Адаптации первого этапа: Space дублирует Insert; Cmd-click переключает пометку; это удобства Mac, а не объявление таких клавиш стандартом FAR. Regex-маски, именованные группы, цитирование разделителей и восстановление прошлого набора Ctrl+M добавлены на этапе 2.

### Этап 3. Движок файловых операций — реализован

Зависимость: этап 1; выполняется до архивов/сети.

- [x] **P3.1** F5/F6 принимают папку либо новое имя; Shift+F5/Shift+F6 работают с объектом под курсором. Массовое переименование с маской имеет предварительный просмотр.
- [x] **P3.2** Диалог конфликтов: заменить, пропустить, новое имя, применить ко всем. Слияние каталогов определяется отдельно от замены файлов. Перезапись начинается только после выбора пользователя.
- [x] **P3.3** Прогресс по файлу и пакету, обработанные байты, очередь, отмена между порциями I/O, повтор ошибки и продолжение. Нельзя показывать успех для частично завершённого пакета.
- [ ] **P3.4** Проверка свободного места, доступов, путей внутри источника, Unicode/регистра, циклов ссылок, пакетов `.app`, внешних/сетевых томов и ошибок отключения диска.
- [x] **P3.5** Сохранять необходимые даты, POSIX-права, extended attributes и resource forks; явно задать поведение hardlink/symlink. Проверить перенос между томами без преждевременного удаления источника.
- [x] **P3.6** Создание ссылок, атрибуты/права, размер папки F3 и свойства папки F4. Корзина остаётся режимом удаления по умолчанию; безвозвратное удаление — отдельная подтверждаемая команда.
- [x] **P3.7** Журнал операций и понятное восстановление после ошибки/прерывания. Отмена не называется undo, если отката нет.

Приёмка: конфликт в середине пакета, нехватка места, запрет записи, файл, изменившийся во время операции, отмена большого копирования, перенос между томами, dangling symlink, совпадение имён по регистру. Проверки изменения данных выполняются на изолированных тестовых каталогах/томах.

Результат этапа 3: последовательная очередь F5/F6 с прогрессом файла/пакета, отменой, явными конфликтами, повтором и журналом до 100 заданий. Панели доступны во время работы. После аварии сохранённые незавершённые задания помечаются прерванными без автоматического запуска. Завершённые изменения не откатываются.

Файл или новое дерево сначала записываются во временный соседний объект; публикация выполняется после проверки источника и назначения. Перенос удаляет только запланированные исходные объекты после проверки опубликованной копии; неожиданные новые файлы сохраняются. Символические ссылки не обходятся, hardlink-копии независимы. Слияние сохраняет существующую папку и её метаданные. Метаданные копируются средствами macOS, включая POSIX-права, даты, ACL, xattr и resource forks.

Адаптация P3.1: групповое переименование использует явный шаблон {name}/{ext}/{n} с обязательным предпросмотром; полный язык масок переименования FAR пока не реализован. P3.6: свойства редактируют POSIX-права выбранного объекта без рекурсии; изменение дат и ACL через интерфейс остаётся расширением. Корзина и подтверждаемое безвозвратное удаление выполняются отдельными командами, вне очереди переноса.

P3.4 оставлен открытым именно для аппаратной приёмки: проверки доступа, ёмкости, вложенности, ссылок, пакета .app и переноса на отдельный APFS-том в образе пройдены. Отключение физического внешнего диска, сбои сетевого тома, заполнение диска во время записи и поведение других файловых систем ещё не проверены. Эти условия не заявлены как пройденные. Итог: 85 автоматических тестов в 7 наборах и UI-сценарии с проверкой файлов на диске — см. журнал.

### Этап 4. Поиск и результаты — локальный режим реализован

Зависимости: маски этапа 1, отменяемые задачи этапа 3.

- [x] **P4.1** Alt+F7: рекурсивный поиск по маске имени, подстроке и regex содержимого, дате, размеру и типу; выбор корней и правил обхода symlink.
- [x] **P4.2** Отмена, инкрементальные результаты, видимые ошибки доступа; ограниченное потребление памяти; отсутствие зависания на циклах/специальных файлах.
- [x] **P4.3** Переход к результату, F3/F4, отправка результатов во временную панель, сохранение параметров поиска.
- [ ] **P4.4** Поиск внутри архивов и удалённых провайдеров остаётся отдельной доработкой после базовых этапов 9–10; подключение провайдера и фильтр текущей папки не заменяют рекурсивный поиск (R9/R15/R16).

Приёмка: найденные результаты совпадают с подготовленным деревом с Unicode, скрытыми файлами, отказом доступа и ссылками; отмена быстро возвращает управление; просмотр результата не сбивает исходные панели.

Реализовано в `FileSearch.swift`, `SearchWindow.swift`, `PanelView.swift` и маршрутизации команд: Alt+F7 / Cmd+Shift+F открывают отдельное окно, Cmd+Enter запускает поиск, Esc отменяет. Маски используют существующие группы; содержимое ищется как подстрока или ICU regex. Размер задан в байтах, даты включают весь местный календарный день. Корней может быть до 128; символические ссылки обходятся только по явному выбору. Параметры сохраняются, автоматического запуска при открытии нет.

Границы P4.1–P4.2: содержимое — UTF-8 без двоичных нулей, целиком в пределах 16 МиБ по умолчанию (настройка 1–64 МиБ). Неподдерживаемое содержимое, отказ доступа, циклы и глубина свыше 128 уровней дают видимые пропуски. Результатов максимум 10000; сохраняются первые 200 сообщений, все ошибки учитываются в счётчике. Обход итеративный, список файлов дерева заранее не загружается, доставка в UI ограничена пакетами до 64 событий. Бюджет ICU на файл — 50 мс с кооперативной отменой; жёсткие сроки на заблокированном файловом вводе-выводе не гарантируются. Поиск внутри архивов и удалённых провайдеров пока отсутствует.

Результаты содержат путь, размер, дату и фрагмент с номером строки. Enter/двойной щелчок переходят к объекту; F3/F4 открывают его без смены путей панелей, через постраничный просмотрщик этапа 5 и редактор этапа 6 до 8 МиБ с шестью кодировками. Временная панель показывает исходную папку, хранит полные пути и проверяет неизменность источников. Обновление и действия удаляют устаревшие строки с видимым счётчиком; копирование и Корзина повторно проверяют снимки после диалога. Возврат восстанавливает папку, курсор, пометки, фильтр и вид. Результаты не сохраняются между запусками.

Проверено: 101 автоматический тест в 8 наборах, включая 16 тестов поиска; UI-сценарии, отмена работающего поиска, лимиты, сохранение параметров, F3/F4, переход, копирование из временной панели и отказ при подмене источника. Подробности — [журнал приёмки](docs/ACCEPTANCE.md).

### Этап 5. Просмотрщик

Зависимость: контракты провайдеров; локальный режим можно начать после этапа 2.

- [x] **P5.1** Потоковое/постраничное чтение больших файлов, позиция/процент, переход по строке и смещению, перенос строк.
- [x] **P5.2** Текст и hex, выбор кодировки и BOM, UTF-8/UTF-16 и востребованные однобайтовые кодировки; отсутствие скрытого преобразования исходного файла.
- [x] **P5.3** Поиск вперёд/назад, регистр, regex, выделение и копирование; история позиции и закладки.
- [ ] **P5.4** Переключение просмотр ↔ редактор с сохранением позиции; просмотр файлов из временной/архивной/сетевой панели через провайдер. **Частично:** F6 в обе стороны для локальных файлов, результатов поиска и временной панели готов; контракт `ViewerByteSource` проверен независимым тестовым источником. ZIP/TAR и SFTP/FTP/FTPS/WebDAV открываются через приватные рабочие копии, полностью загруженные до открытия окна. Переход из архивного/сетевого просмотра в редактор поддержан; обратный F6 с сохранением связи с источником остаётся в R15/R16. Потоковое чтение прямо с удалённого источника не заявлено.

Приёмка: большие и бинарные файлы открываются без загрузки целиком в NSTextView; поиск на границе блоков; неверная кодировка не приводит к записи повреждённых данных.

Реализация: ограниченный блок 64 КиБ, фоновые чтение/поиск/проход к строке, отмена и проверка версии файла; UTF-8/UTF-16 LE/BE, Windows-1251/1252, Latin-1, BOM. Поиск буквальный, hex и построчный ICU regex; регистр и оба направления. Regex ограничен строкой в 1 МиБ исходных байтов и кооперативным бюджетом 50 мс; полного совпадения диалекта с FAR нет. Выделение/копирование ограничено текущим блоком; автоматического циклического поиска нет. История 100 файлов, до 20 закладок, позиции и закладки сбрасываются при смене версии источника. Связанный редактор этапа 6 поддерживает те же шесть кодировок до 8 МиБ и отказывает в необратимом декодировании.

Сверка с официальными `viewer.cpp` и `FarRus.hlf.m4` закреплённого FAR: [VIEWER_REFERENCE.md](docs/VIEWER_REFERENCE.md). Проверки: 123 теста в 10 наборах и UI-сценарии в [журнале приёмки](docs/ACCEPTANCE.md).

### Этап 6. Редактор — реализован в указанных границах

Зависимости: этап 5 для кодировок и позиционирования, этап 3 для сохранения.

- [x] **P6.1** Поиск/замена, regex, переход к строке, номера строк, отступы, Tab-настройки, нормальный и прямоугольный блок, undo/redo. Regex построчный Foundation/ICU; прямоугольник задаётся отдельным диалогом строк/колонок, составные правки имеют одну операцию undo.
- [x] **P6.2** Новые файлы, Save As, выбор кодировки и CRLF/LF, BOM; несколько документов, переключение окон и история позиций. Шесть кодировок; обычное сохранение сохраняет исходный формат, повторное открытие активирует существующий буфер.
- [x] **P6.3** Обнаружение внешнего изменения с вариантами перечитать/сохранить копию/сравнить; восстановление несохранённого текста после сбоя. Сравнение открывает отдельную версию с диска только для чтения, без автоматического diff/слияния; восстановление открывает последний записанный черновик и не перезаписывает источник автоматически.
- [x] **P6.4** Подсветка синтаксиса и расширения редактора через отдельный механизм; ясное ограничение размера до реализации редактирования больших файлов. Фоновая лексическая подсветка Swift/JSON/shell до 256 КиБ, интерфейс `EditorSyntaxProvider`; это собственное расширение Swift, без загрузки DLL FAR. Редактирование ограничено 8 МиБ.

Приёмка: запись не меняет кодировку/концы строк без решения пользователя; внешний конфликт не теряет буфер; закрытие/выход/перезапуск приложения не теряют подтверждённо сохранённые данные; обратимость замен через undo.

Реализация разделена на `EditorDocument`, `EditorRecoveryStore`, `EditorEditing`, `EditorSyntaxProvider` в FarCore и `TextFileWindow` в AppKit. Доступны UTF-8, UTF-16 LE/BE, Windows-1251/1252, Latin-1. Снимок хранит исходные байты, разрешённый путь и идентичность источника. Строгое декодирование и обратное кодирование проверяют отсутствие потерь; непредставимые символы, неправильные последовательности и неопределённые байты кодовой страницы дают отказ. BOM и смешанные CR/LF/CRLF сохраняются по умолчанию, преобразование в LF/CRLF выполняется только явным выбором Save As. Новые документы используют UTF-8 без BOM, ввод новой строки — LF; вставка сохраняет полученные окончания строк. F6 переводит позиции исходных байтов в UTF-16 и обратно с учётом BOM и целых Unicode-скаляров.

Сохранение использует временный файл рядом с назначением, перенос метаданных и атомарную публикацию. Замена требует конкретного снимка назначения и повторно проверяет идентичность, байты и цель ссылки. Создание нового файла публикуется исключительно, без замены внезапно появившегося объекта. Проверки согласуются через `NSFileCoordinator`; некоординирующая внешняя запись всё ещё может попасть между последней проверкой и rename — атомарного сравнения идентичности и замены файловая система не предоставляет. Внешний конфликт оставляет буфер доступным; перечитывание грязного буфера требует отдельного решения. Черновики хранятся атомарно в приватном Application Support/FarForMac/Recovery (каталог 0700, файлы 0600). Здоровые записи восстанавливаются даже при повреждённых соседних; ошибки и предел загрузки 100 записей/64 МиБ сообщаются, пропущенные файлы не удаляются. После сбоя доступны последние записанные черновики, изменения до следующей записи могут не успеть сохраниться.

Границы P6.1: regex работает внутри строки до 1 МиБ текста UTF-8, с кооперативным бюджетом 50 мс на строку; жёсткий таймаут и тождество диалекту FAR не обещаются. Замены и прямоугольные операции ограничивают размер результата и число изменений, интерфейс дополнительно проверяет предел файла 8 МиБ в выбранной кодировке. Переход поддерживает абсолютные строку/колонку с 1; полного синтаксиса FAR, постоянных блоков, всех Alt-сочетаний и редакторских закладок пока нет. Подсветка — ограниченный лексический анализ, не полный разбор языков. Остаточный паритет вынесен в R12.

После этапа 6 проходят 157 тестов в 14 наборах: кодировки/BOM/EOL, ошибки и конфликты, метаданные, Unicode-позиции, поиск/замены и прямоугольники, пределы операций, подсветка и восстановление. Сверка по закреплённым `editor.cpp`, `fileedit.cpp` и справке: [EDITOR_REFERENCE.md](docs/EDITOR_REFERENCE.md). Результаты UI-проверок — в [журнале приёмки](docs/ACCEPTANCE.md).

### Этап 7. Командная строка и пользовательское меню — реализован в указанных границах

Зависимость: стабильная маршрутизация клавиш этапа 2.

- [x] **P7.1** Встроенная строка команд в каталоге активной панели: выполнение отдельным shell, дополнение буквальных путей по Tab/Ctrl+Space и история; простой буквальный `cd` меняет активную панель, составные команды выполняются целиком без смены её пути.
- [x] **P7.2** Настоящая PTY-сессия с shell пользователя, вывод, ввод, resize, сигналы и остановка; Ctrl+O скрывает/возвращает панели. Явный Shell открывает интерактивную сессию; экран — базовый монохромный VT100 с указанными ниже ограничениями.
- [x] **P7.3** F2 — настраиваемое пользовательское меню с командами, подменю, локальной/общей JSON-конфигурацией и безопасными подстановками имени/пути/пометок; перед выполнением показываются источник, каталог и готовая команда.
- [x] **P7.4** Глобальные ассоциации execute/view/edit по маске; общая история команд/просмотра/редактора/папок до 500 записей суммарно с удалением записи и очисткой категории. Выбор команды только вставляет текст без выполнения.

Приёмка: пути с пробелами, кавычками, Unicode и shell-метасимволами; интерактивная команда получает ввод; отмена не завершает приложение; команды из файлов меню не выполняются просто при просмотре каталога.

Реализация: `ShellCommand`, `TerminalSession`, `TerminalScreen`, `CommandHistory`, `UserCommands` в FarCore и `ShellWorkspace`/`UserCommandsWindow` в AppKit. Каждая команда строки передаётся отдельному shell в режиме `-c`; состояние переменных/функций и смена cwd между такими запусками не сохраняются. Кнопка Shell явно открывает длительную интерактивную сессию. Её cwd меняется только внутри сессии и не двигает панели. Простой буквальный `cd [--] [путь]`, `cd ~` и `cd -` обрабатываются до запуска shell с обновлением панели после успешного чтения. `cd -` относится к предыдущему активному контексту, включая переключение между панелями. Подстановки shell, перенаправления и составные команды целиком делегируются shell и не изменяют путь панели.

PTY обеспечивает управляющий терминал, ввод, изменение размера, Ctrl+C и остановку; закрытие приложения с работающей сессией требует явного решения. Монохромный экран интерпретирует базовые перемещения/очистку VT100, но не является полным эмулятором xterm: SGR-атрибуты/цвета, OSC и часть расширенных терминальных режимов игнорируются. Точная совместимость произвольных полноэкранных программ не заявляется; непрерывное состояние shell и полнота эмуляции остаются в R13.

Глобальный `Application Support/FarForMac/commands.json` редактируется отдельным окном JSON с примером и проверкой при сохранении. Локальный `.farformac-menu.json` читается только при явном F2, целиком заменяет общее меню и редактируется обычным F4 при показе скрытых файлов. Переход по папкам/чтение файла команд не выполняют. Ассоциации берутся только из глобальной конфигурации, дают выбор совпадений и стандартного действия. Параметры `{name}`, `{path}`, `{marked}`, `{active}`, `{passive}` заключаются в POSIX-кавычки; `{marked}` использует только реальные пометки и требует непустого набора. Неизвестные/неоднозначные параметры отклоняются. Это собственный JSON-формат, а не совместимость с FarMenu.ini или всеми метасимволами FAR.

Общая история хранится приватно в `Application Support/FarForMac/History/activities.json`, ограничена 500 записями суммарно и 8 МиБ файла. Удаление и очистка действуют на выбранную категорию. Существующие истории переходов панелей до 100 записей, позиции/кодировки редактора и просмотрщика сохраняются отдельно; удаление из общей истории не очищает эти хранилища. Подробная сверка официальных исходников и ограничения: [COMMAND_REFERENCE.md](docs/COMMAND_REFERENCE.md). Итог проверок этапа фиксируется отдельно в [журнале приёмки](docs/ACCEPTANCE.md).

### Этап 8. Дополнительные панели и сравнение — реализован в указанных границах

Зависимости: этапы 2–4.

- [x] **P8.1** Режимы «Файлы», дерево каталогов, информация и быстрый просмотр; фоновое чтение и отмена. Ctrl+T/L/Q переключают режим активной панели, Esc возвращает файлы. Дерево загружает ветви по запросу; информация и быстрый просмотр следят за курсором соседней файловой панели. Размер папки считается без обхода ссылок.
- [x] **P8.2** Временная панель из поиска и вручную добавленных объектов разных каталогов. Полный путь различает одинаковые имена, исходные снимки проверяются перед действиями и после перезапуска. F7 убирает запись без удаления файла; Ctrl+PageUp открывает исходную папку. Возврат восстанавливает обычный контекст.
- [x] **P8.3** Фоновое сравнение непосредственных файлов каталогов по имени/размеру/времени и опционально байтам, отмена, пометка видимых отличий и предпросмотр выбранного направления синхронизации. Сравнение и план не изменяют данные; перед пометкой/планом снимок проверяется заново.
- [x] **P8.4** Сохранение режима, пути, курсора, фильтра, активной стороны и временных записей при обычном выходе/явном сохранении. Колонки, ширины, сортировка и история используют существующее хранение. Чтение/правка UTF-8 `descript.ion`, колонка описания; верхние/нижние группы масок для сортировки по имени/расширению. Окна настроек защищают несохранённые правки.

Границы: дерево — до 10 000 дочерних каталогов за запрос, без кэша всего диска и сохранения раскрытых ветвей. Превью — первые 64 КиБ текста или 4 КиБ HEX; полный просмотр доступен F3 из файловой панели. Подсчёт размера ограничен глубиной 128, учитывает скрытые объекты и каждую запись hardlink, показывает неполный результат при ошибках; отмена кооперативная между системными вызовами.

Сравнение, как базовый CompareDir FAR, не рекурсивное: папки, ссылки, специальные файлы и конфликты показаны отдельно. До 10 000 записей на каталог, проверка байтов — до 64 МиБ на файл и 512 МиБ суммарного чтения. Неточные/неполные результаты не дают активного плана и пометок. План отображает до 1000 строк, не предлагает удаление и не запускает синхронизацию. Пометки применяются только к видимым строкам панелей, число явно показано.

Сессия ограничена 10 000 временных записей/8 МиБ на панель, пометки после запуска не восстанавливаются. Устаревший объект исключается, а новый по тому же пути не подставляется. Описания ограничены 2 МиБ/20 000 строк; поддержаны UTF-8/BOM, кавычки и продолжения. Изменение проверяется перед атомарным сохранением; неподдерживаемая кодировка/неоднозначный формат не переписываются. Описания ещё не переносятся автоматически при F5/F6/переименовании. Группы — до 100 правил с общим бюджетом проверки; порядок групп не переворачивается вместе с именами. Остаточный паритет сохранён в R14.

Сверка официальных исходников: [панели](docs/PANELS_REFERENCE.md), [временная панель](docs/TEMPORARY_PANEL_REFERENCE.md), [сравнение](docs/COMPARISON_REFERENCE.md), [описания и сортировка](docs/METADATA_REFERENCE.md). Проверки: [ACCEPTANCE.md](docs/ACCEPTANCE.md).

### Этап 9. Архивы как файловая панель — базовые ZIP и несжатый TAR

Зависимости: интерфейс провайдеров, этапы 3–5.

- [x] **P9.1** Выбрана системная libarchive; проверенная версия macOS поставляет 3.7.4. ZIP и несжатый TAR, возможности чтения/записи, BSD-уведомления и ограничения опубликованы в [ARCHIVE_FORMATS.md](docs/ARCHIVE_FORMATS.md). 7z/RAR и расширенные варианты ZIP/TAR — R15.
- [x] **P9.2** Базовые ZIP/TAR: отдельная архивная панель, навигация/пометки, просмотр через рабочую копию, извлечение в обычную папку через очередь, создание/добавление/удаление. Для ZIP с ZipCrypto/AES-256 — чтение с паролем в памяти, без изменения зашифрованного архива. Ошибки пароля, повреждения и изменения источника различаются; целостность данных проверяется при извлечении.
- [x] **P9.3** F4 открывает приватную рабочую копию; сохранение в архив — отдельное явное действие. Создание/изменение незашифрованных ZIP/TAR пишет соседний временный файл, проверяет результат и идентичность источников, затем безопасно публикует архив. Отмена до публикации сохраняет исходный архив; внешняя подмена не перезаписывается.
- [x] **P9.4** Все пути проверяются до записи: обходы, абсолютные/Windows-пути, NUL, коллизии регистра/NFC, конфликты иерархии; ссылки и специальные файлы отвергаются. Извлечение только в приватную папку с дескрипторным обходом без следования ссылкам; лимиты числа элементов, реальных байтов и степени распаковки, кооперативная отмена. Вложенные архивы — R15.

Приёмка: набор обычных/повреждённых/зашифрованных архивов; имена Unicode; конфликт файлов; прерывание записи; выход за каталог извлечения невозможен.

## 6. Реестр отличий macOS

| Поведение | Решение |
| --- | --- |
| Буквы дисков Windows | Корень, `/Volumes`, домашняя папка и избранные места |
| F-клавиши, Insert и numpad | Сохранить оригинальные команды; добавить меню и явные Mac-дубли, не перехватывать системные сочетания вне панели |
| NTFS ADS, ACL, атрибуты Windows | Отдельная карта соответствия POSIX/ACL/xattr; невозможные операции отключены, не имитируются |
| Удаление | Корзина macOS по умолчанию; постоянное удаление только отдельной командой с подтверждением |
| Регистронезависимые FAR-маски и регистр ФС | Маски и идентичность файлов различаются: матчинг не должен объединять разные реальные файлы |
| Команды shell | Shell пользователя на macOS, без обещания выполнения Windows cmd/batch |
| DLL-плагины | Собственный API/портирование исходников по отдельным контрактам |
| Новый текстовый документ | UTF-8 без BOM, ввод LF; исходный формат открытого файла сохраняется, преобразование LF/CRLF выбирается явно |
| Скрытые помеченные элементы | На первом этапе скрытие фильтром снимает пометки; правило явно показано в помощи |
