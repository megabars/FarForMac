# Архивы: сверка с закреплённым FAR

Эталон — официальный FAR 3.0 build 6747, commit
`1a6b02544b339615232078e0551463ef15b73ff9`, закреплённый в
[spec.md](../spec.md). Прочитаны реальные исходники ArcLite и русская справка
этого снимка. Сравнивается поведение; исходный код FAR/ArcLite в приложение
не переносился, совместимость с DLL-плагинами и полная совместимость ArcLite
не заявлены.

Дополнительно для R15.2 через GitHub connector прочитаны фактические
[ArcLite open.cpp](https://github.com/FarGroup/FarManager/blob/1a6b02544b339615232078e0551463ef15b73ff9/plugins/arclite/open.cpp):
`Archive::detect` сочетает сигнатуры и расширения, `Archive::open` получает
поток главного файла родительского контейнера, сохраняет `parent`/`arc_chain` и
продолжает обнаружение. FarForMac использует явное открытие выбранного члена,
приватные рабочие копии, ограниченную глубину и чтение без обратной записи;
это собственная ограниченная адаптация цепочки, а не полное поведение ArcLite.
[Archive::set_properties в update.cpp](https://github.com/FarGroup/FarManager/blob/1a6b02544b339615232078e0551463ef15b73ff9/plugins/arclite/update.cpp#L808)
выбирает формат, метод и параметры сжатия. Наш writer сохраняет только
проверенный формат/вид фильтра; полный выбор методов и уровней ArcLite не заявлен.

## Сопоставление с FarForMac

| Семантика FAR/ArcLite | Реализация FarForMac | Граница |
| --- | --- | --- |
| `SetDirectoryW` / `Plugin::set_dir` | `ArchivePanelView` хранит виртуальный каталог; Enter и родительская строка меняют его, выход восстанавливает локальную панель | Вложенные поддержанные архивы открываются цепочкой кадров, возвращение восстанавливает родительскую панель; состояние между запусками не сохраняется |
| `GetFindDataW` / `Plugin::list` | `ArchiveReader.open` создаёт проверенный снимок; панель показывает непосредственные записи и неявные родительские каталоги, отдельные курсор и пометки | ZIP/ZIP64 и TAR (none/gzip/bzip2/xz); открытие списка проверяет заголовки, а не все данные/CRC/пароль |
| Ctrl-PgDn / Enter | Явное открытие выбранного локального файла как архива; Enter использует поддержанный архивный сценарий | SFX и принудительный Ctrl+Shift+PgDn из FAR не заявлены |
| `GetFilesW` / F5 из архива | `ArchiveReader.extract` извлекает выбранное в новую приватную папку; затем `TransferEngine` и очередь копируют в назначение с обычными конфликтами | Перенос с удалением из архива, добавление в конец существующего файла, пауза и приоритет ArcLite не реализованы |
| Пароль извлечения | `ArchiveOperationController` запрашивает пароль; libarchive получает его через C API в памяти, рабочая копия удерживается до окончания использования | Проверены ZipCrypto и AES-256; неверный/отсутствующий пароль различаются, изменение шифрованных архивов запрещено |
| `PutFilesW` / F5 с противоположной панели | F5 с обычной панели добавляет выбранные локальные файлы в текущую папку соседнего архива через `ArchiveWriter.update`; создание ZIP/TAR, TAR.GZ/BZ2/XZ доступно в меню | Источники не удаляются, копирование между двумя архивами и все параметры сжатия/шифрования ArcLite не заявлены |
| `DeleteFilesW` | Выбранные пути и их потомки удаляются через пересборку ZIP/TAR после подтверждения | Это изменение архива, без Корзины и без общего undo |
| `MakeDirectoryW` / F7 | `ArchiveWriter.createDirectory` добавляет явную пустую папку в текущий архивный каталог; новые родители допустимы | Поддержанные ZIP/TAR без шифрования, кроме вложенных панелей; совпадение с существующим явным/неявным каталогом или файлом даёт отказ |
| Внутреннее перемещение и переименование | F6 передаёт выбранные деревья и новые полные пути в `ArchiveWriter.move`; вся операция публикуется одной заменой архива | Это отдельная адаптация FarForMac: закреплённые `get_files`/`put_files` ArcLite используют Move при извлечении/добавлении. Слияние, перезапись и перемещение между двумя архивами не заявлены |
| Просмотр/редактирование архивного файла | F3/F4 используют приватную рабочую копию; редактор сохраняет её отдельно, `ArchiveEditCommitWindow` явно применяет изменения в архив | F6 рабочей копии возвращает в тот же редактор с позицией; запись в архив остаётся отдельной командой. Зашифрованные и вложенные архивы не редактируются |
| Отмена и ошибки | Фоновая операция, прогресс, кооперативная отмена, явные ошибки пароля/повреждения/устаревшего источника | После передачи извлечённых файлов в обычную очередь действует её частичный результат: завершённые копии сохраняются при отмене |

Пути и данные читаются через собственное ядро Swift и системную libarchive,
а не через реализацию Plugin API FAR. Сопоставление выше фиксирует назначение
операций, не тождество интерфейсов, всех клавиш или результатов на каждом формате.

## Безопасность записи и оставшийся объём

`ArchiveReader` проверяет все заголовки до создания выходных файлов, включая
невыбранные записи; отклоняет опасные пути, коллизии регистра/NFC, ссылки и
специальные файлы. Данные идут порциями с проверкой фактических размеров,
суммарного бюджета и степени распаковки. Выход возможен только в новую приватную
рабочую папку с дескрипторным обходом без следования ссылкам. Пределы и точная
матрица возможностей опубликованы в [ARCHIVE_FORMATS.md](ARCHIVE_FORMATS.md).

`ArchiveWriter` проверяет источники, пишет соседний временный архив, перечитывает
и сравнивает результат, затем публикует его с повторной проверкой назначения.
При замене старый объект сохраняется до проверки его идентичности после
атомарного обмена. Отмена до публикации сохраняет исходный архив. Сохранение
редактора меняет только рабочую копию; применение в архив — отдельное действие,
которое повторно проверяет исходный снимок.

Открыты ZIP64, SFX, многотомные ZIP, сжатые TAR, 7z/RAR, вложенные архивы,
создание/изменение шифрованных архивов, расширение поиска P4.4,
перемещение между архивами/на локальную панель с удалением источника,
слияние/перезапись при внутреннем F6 и точность всех метаданных. F7 и внутренний
F6 реализованы для проверенных ZIP/несжатого TAR; F6 рабочей копии закрыт в P5.4.
Приватные рабочие файлы создаются с
правами 0600, каталоги — 0700; это не гарантия восстановления всех прав,
исполняемости, владельцев, дат, ACL, xattr и resource forks исходного формата.
Полный остаточный план — R15 в [spec.md](../spec.md).

После этапа 9 проходят 243 автоматических теста в 26 наборах. Архивные тесты
покрывают ZIP/TAR и пустые архивы, Unicode, ZipCrypto/AES-256, ошибки пароля,
CRC/усечение, обходы пути и нормализацию ZIP, NUL, коллизии имён/иерархии,
ссылки/FIFO, лимиты и отмену, безопасное обновление и внешнюю замену.
Эти тесты не подтверждают прохождение интерфейса: выполненные ручные сценарии
и их ограничения фиксируются отдельно в [ACCEPTANCE.md](ACCEPTANCE.md).

R15.2 проверяет отдельными фикстурами сжатые TAR, небольшой ZIP64 и вложенную
навигацию. Для вложенных панелей `ArchiveSnapshot.isReadOnly` проверяется также
в ядре записи, поэтому F6/F7/обновление не могут незаметно изменить временный
контейнер. Снимок удерживает источник независимо от жизни панели и сверяет всех
предков. Сохраняющиеся границы: 7z/RAR, SFX, многотомность, запись шифрования,
обратная запись вложенных архивов и полная верность метаданных.
