# FAR Commands

Эталон — плагин FARCmds в FarGroup/FarManager на коммите `1a6b02544b339615232078e0551463ef15b73ff9`. Справка перечисляет `view:`, `edit:`, `goto:`, `clip:`, `whereis:`, `link:`, `run:`, `load:` и `unload:`. Плагин принимает эти команды также из пользовательского меню и ассоциаций, когда они поступают в общий обработчик командной строки. [FARCmdsEng.hlf](https://github.com/FarGroup/FarManager/blob/1a6b02544b339615232078e0551463ef15b73ff9/plugins/farcmds/FARCmdsEng.hlf), [FARCmds.cpp](https://github.com/FarGroup/FarManager/blob/1a6b02544b339615232078e0551463ef15b73ff9/plugins/farcmds/FARCmds.cpp).

| Команда | Поведение в исходниках |
| --- | --- |
| `view:файл`, `edit:файл` | Открывают просмотрщик или редактор. Для `edit:` можно передать `[строка,столбец]` непосредственно после двоеточия. Пустой компонент означает позицию по умолчанию. Пробел перед именем позволяет открыть файл, начинающийся со скобки. Настройка разрешает редактировать ещё не созданный файл. |
| `goto:путь`, `goto:<файл` | Выбирают объект в панели. Завершающий разделитель у каталога означает переход внутрь него. Форма `<файл` берёт путь из первой строки файла. Отдельная ветка распознаёт Windows Shell Link. |
| `whereis:имя`, `whereis:<файл` | Ищут исходное имя в текущей папке, `FARHOME` и `PATH`, потом варианты из `PATHEXT`. Windows дополнительно проверяет системные папки и App Paths из реестра. Найденный объект передаётся механизму перехода. |
| `clip:файл`, `clip:<команда` | Копируют прочитанный текст до первого NUL. Файл нулевой длины очищает буфер. Объём чтения задаётся в настройках. |
| `link:[/msg] [/n] [/s] источник назначение` | Для файла создают жёсткую ссылку, с `/s` создают символическую. Windows использует junction для папок и volume mount point для букв дисков. `/msg` включает сообщения об ошибках, `/n` сохраняет состояние панели без немедленного обновления. |
| `run:файл<команда` | Запускает команду и сохраняет выбранные потоки в файл. |
| `load:путь`, `unload:путь` | Загружают и выгружают плагины. Форма `<файл` читает путь из файла. `unload:` также принимает GUID. |

Для `view`, `edit`, `clip` и `run` маркер `<` вводит команду оболочки. `1` выбирает stdout, `2` stderr, `*` объединяет их в одном файле, `?` разделяет. Режимы `>`, `<` и `+` управляют отображением вывода. В начале команды допускается `|рабочая папка|`. Код `GetStreamAndMode` разрешает режим без явного потока и выбирает `1`/`2` по первому символу после маркера. Код сохраняет раздельные потоки для `clip:<?`, затем берёт в буфер stdout. Для `run:<?` оба потока объединяются. При раздельных потоках режим дублирования снижается до обычного сохранения экрана. [OpenCmd.cpp](https://github.com/FarGroup/FarManager/blob/1a6b02544b339615232078e0551463ef15b73ff9/plugins/farcmds/OpenCmd.cpp#L533).

Исходники отправляют команду процессору `COMSPEC`, создают временные файлы, отключают историю для окон с выводом и удаляют временные файлы при закрытии этих окон. Значения по умолчанию — скрытый вывод, объединённый поток, открытие пустого результата, разрешение редактирования нового файла и предел чтения 1 МиБ. [OpenCmd.cpp](https://github.com/FarGroup/FarManager/blob/1a6b02544b339615232078e0551463ef15b73ff9/plugins/farcmds/OpenCmd.cpp#L1576), [FARCmds.cpp](https://github.com/FarGroup/FarManager/blob/1a6b02544b339615232078e0551463ef15b73ff9/plugins/farcmds/FARCmds.cpp).

## Реализация FarForMac

- Команда выполняется в выбранной папке через `/bin/zsh -c` с переменными командного окружения FarForMac. `|путь|` задаёт другую папку. `%ИМЯ%` раскрывается для совместимости с синтаксисом FAR. Процесс и обычные дочерние процессы находятся в отдельной POSIX-группе. Отмена останавливает эту группу и прекращает дальнейшие действия команды.
- Перехваченные потоки сохраняются побайтно. Для `view:<?` и `edit:<?` создаются раздельные рабочие файлы. Они удаляются после закрытия последнего связанного окна. `run:` записывает указанный файл атомарно после получения вывода. Код завершения и размер показаны в строке состояния.
- `<>` скрывает перехваченный вывод. `<<` сохраняет неперехваченный поток в терминале. `<+` также дублирует перехваченный поток. Текст доступен в существующей поверхности терминала после завершения команды. Windows console API и приложения, требующие интерактивного TTY, для этих префиксов остаются открытыми.
- Предел чтения для `clip:`, `goto:<`, `whereis:<`, `load:<` и `unload:<` настраивается от 1 байта до 16 МиБ. 0 восстанавливает значение 1 МиБ. Для внешнего процесса действуют отдельные пределы 60 секунд и 16 МиБ суммарного читаемого вывода. Пределы и отмена проверяются до открытия рабочих окон или записи целевого файла.
- Переход и поиск работают с локальными путями macOS. Для перехода внутрь папки используется завершающий `/`. `whereis:` проверяет текущую папку, `FARHOME`, `PATH` и настроенные варианты `PATHEXT`. Windows `.lnk`, реестр и системные папки Windows остаются открытыми.
- `link:` создаёт жёсткую ссылку для обычного файла и символическую с `/s`. Для папки нужен `/s`. Windows junction и монтирование по букве диска остаются открытыми.
- `load:` и `unload:` управляют доступными LuaFar-расширениями. Выгрузка принимает путь к исходнику или GUID. Windows DLL остаются открытыми.

Тесты проверяют синтаксис всех префиксов, реальные потоки stdout/stderr, код завершения, рабочую папку и окружение, отмену и завершение группы процессов, ограничения вывода, UTF-16/NUL, чтение пути и порядок поиска. Отдельный сценарий AppKit открывает оба потока в просмотрщиках, проверяет удаление рабочих файлов, запись `run:` и позицию редактора.
