## Командная строка и терминальная сессия

По умолчанию строка команд работает в каталоге активной панели: Enter отправляет команду новому shell пользователя с `-c`. Флажок «Сохранять состояние shell» включает постоянную сессию, описанную ниже. Кнопка Shell явно открывает длительную интерактивную сессию. В ней состояние и рабочий каталог живут до завершения сессии; её `cd` не перемещает панели. Переключение Ctrl+O скрывает/возвращает панели, сохраняя работающую сессию. Открытие Terminal.app остаётся отдельной внешней командой.

Простое буквальное `cd [--] [путь]` обрабатывается до запуска процесса и меняет активную панель только после успешного чтения назначения. Без аргумента или с `~` используется домашняя папка; `cd -` возвращает предыдущий активный контекст, включая переключение между панелями. Кавычки защищают буквальные пробелы/апострофы; quoted `~` и `-` являются именами папок. Составные команды, подстановки, перенаправления, переменные и glob передаются shell целиком: `cd /tmp && pwd` не меняет панель.

Tab/Ctrl+Space дополняют последний буквальный путь с безопасным quoting, включая незавершённые кавычки. Дополнение не запускает shell, не подставляет переменные и не выполняет command substitution. При нескольких совпадениях пользователь выбирает путь; выполнение команды требует отдельного Enter. Просматривается до 1000 записей каталога, выводится до 100 кандидатов; при достижении предела результат явно отмечается как неполный.

`TerminalSession` даёт программе настоящий управляющий PTY, ввод, изменение размера, Ctrl+C и остановку. Обычный pipe не подменяет терминал. Вывод получает `TerminalScreen` с перемещениями курсора, очисткой, ограниченной прокруткой и SGR 16/256/RGB. Атрибуты доходят до AppKit как форматированный текст; дополнительные режимы и пределы описаны ниже. Полной xterm-эмуляции, точной Unicode-ширины и гарантированной совместимости любых полноэкранных программ нет. Это явные пределы этапа 7, а не заявление о полном паритете терминального поведения FAR/Windows.

## Истории действий

Приватный `Application Support/FarForMac/History/activities.json` содержит категории command/view/edit/folder и до 500 записей суммарно. Команда хранит каталог отправки; одинаковая запись перемещается к началу, а одинаковые команды из разных каталогов остаются разными. Файл ограничен 8 МиБ; повреждённый/слишком большой файл даёт ошибку, не выполняется и не удаляется при загрузке.

В истории можно удалить запись или очистить выбранную категорию. Выбор команды только вставляет её текст в строку без запуска; Enter выполняет её в текущем активном каталоге. Стрелки вверх/вниз в командной строке перебирают команды без выполнения. Прежние истории переходов отдельных панелей до 100 записей и сохранённые позиции/кодировки просмотрщика/редактора остаются самостоятельными хранилищами; удаление из общего списка их не очищает.

## Конфигурация FarForMac

Глобальный файл: `~/Library/Application Support/FarForMac/commands.json`. Окно «Меню пользователя и ассоциации» редактирует UTF-8 JSON, показывает пример и проверяет структуру перед сохранением. Новый файл записывается атомарно с правами `0600`; новая папка конфигурации создаётся с `0700`. Просмотр и проверка файла ничего не запускают.

```json
{
  "version": 1,
  "menu": [
    { "title": "Имя текущего файла", "key": "1", "command": "printf '%s\\n' {name}" },
    { "title": "Папки", "children": [
      { "title": "Пассивная папка", "command": "ls -la -- {passive}" }
    ] }
  ],
  "associations": [
    { "title": "Сведения о тексте", "mask": "*.txt,*.md", "execute": "file -- {path}" }
  ]
}
```

`version` обязателен и равен 1. `menu` и `associations` можно опустить. У пункта меню есть непустой `title` и ровно одно из `command` или непустого массива `children`. Необязательный `key` — одна буква, цифра или F1–F24, уникальная без учёта регистра на текущем уровне. Разделитель задаётся как `{ "title": "—", "separator": true }` без команды, подменю и клавиши. У ассоциации есть `title`, `mask` и хотя бы одна команда `execute`, `view`, `edit`, `alternateExecute`, `alternateView` или `alternateEdit`. Маски используют существующий `FileMask`: списки, исключения, glob и явные ICU-регулярные выражения. При нескольких совпадениях сохраняется порядок конфигурации; выбираются лишь ассоциации, имеющие запрошенное действие.

По F2 явно читается `.farformac-menu.json` непосредственно в активной папке. Его `menu` целиком заменяет глобальное меню; при отсутствии файла используется глобальное. Переходы по папкам не читают локальные команды и ничего не запускают. Ошибка локального файла показывается пользователю: молчаливого перехода к глобальному меню нет. Локальные ассоциации не применяются. Выполнение локального пункта требует просмотра названия, полного пути источника, рабочего каталога и окончательной команды. Файлы меню, найденные в родительских папках, автоматически не подхватываются.

Чтобы создать локальное меню, скопируйте пример в `.farformac-menu.json` в нужной папке и оставьте поля `version` и `menu`. Для изменения существующего файла включите показ скрытых файлов и откройте его встроенным редактором по F4; при настроенной ассоциации JSON выберите «Стандартное действие». JSON проверяется при следующем F2; редактирование файла команд не выполняет.

## Параметры команд

| Параметр | Подстановка |
| --- | --- |
| `{name}` | Полное имя текущего файла с расширением, без каталога |
| `{path}` | Полный путь текущего файла |
| `{stem}`, `{extension}` | Имя без последнего расширения; последнее расширение без точки |
| `{marked}` | Отдельные полные пути всех помеченных файлов |
| `{active}` | Полный путь активного каталога |
| `{passive}` | Полный путь пассивного каталога |
| `{passiveName}`, `{passivePath}`, `{passiveStem}`, `{passiveExtension}` | Имя, путь и части имени текущего файла пассивной панели |
| `{passiveMarked}` | Отдельные полные пути реальных пометок пассивной панели |
| `{selectedNames}`, `{passiveSelectedNames}` | Имена помеченных файлов, без пометок — имя текущего файла; для импорта FAR `!&` |
| `{input:Название}`, `{input:Название|начальный текст}` | Значение из диалога; одно буквальное слово shell, включая пустую строку |
| `{list}`, `{list0}` | Путь приватного UTF-8 list-файла с полными путями, разделитель LF или NUL |
| `{listNames}`, `{listNames0}` | Такой же list-файл с именами без каталога |
| `{passiveList}`, `{passiveList0}`, `{passiveListNames}`, `{passiveListNames0}` | List-файлы выбранных файлов пассивной панели |

Каждое значение заключено в POSIX single quotes с безопасной обработкой апострофов, пробелов, переводов строк и shell-символов. Параметры должны стоять отдельными словами без дополнительных кавычек: `cat -- {path}`. Варианты `"{path}"`, `prefix{path}`, экранированные параметры и неизвестные имена отвергаются. Если текущего файла или реальных пометок нет, требующая их команда не запускается. List-файлы используют пометки в их текущем порядке, а без пометок — текущий файл соответствующей панели.

Параметры разрешены только в однострочных шаблонах без command substitution, backticks, here-document и некавыченных shell-комментариев `#`. В комментарии shell игнорирует защитные кавычки; поэтому шаблон с параметрами и таким комментарием целиком отклоняется до подготовки/исполнения. Кавыченный `'#'` и `literal#word` разрешены. Для более сложной логики используется отдельный скрипт, которому параметры передаются аргументами. Содержимое конфигурации является программой shell: безопасное quoting защищает значения имён файлов, но не изменяет смысл явно заданной команды, например `eval`, и не предотвращает трактовку аргумента как опции самой программой. Для файловых аргументов используйте `--`, когда программа это поддерживает.

## Пределы и проверки

Чтение ограничено 256 КиБ; JSON — 24 структурными уровнями, меню — 8 уровнями и 512 пунктами, ассоциации — 256 записями. Название ограничено 512 байтами и не содержит управляющих символов; шаблон команды ограничен 16 КиБ. Файлы открываются с `O_NONBLOCK | O_NOFOLLOW`, проверяются через `fstat` и должны быть обычными файлами. FIFO, каталоги, конечные символические ссылки и слишком большие файлы отвергаются. Неизвестные поля конфигурации также считаются ошибками, чтобы опечатки не меняли поведение незаметно.

Автоматические проверки покрывают вложенность и структуру меню, маски и действия ассоциаций, особые символы и shell injection в именах файлов, неправильные параметры, приоритет локальной конфигурации, происхождение меню, отсутствие исполнения при чтении, повреждённые/слишком большие файлы, FIFO, ссылки, права нового глобального файла и сохранность предыдущей конфигурации при ошибке проверки.

Оставшиеся отличия от FAR: основной формат JSON; одна команда shell на пункт вместо отдельного списка CommandX; нет переключения трёх профилей и поиска меню родителей, встроенного редактора отдельных записей, метасимволов заголовков, short names, историй/переменных и вложенных выражений интерактивного ввода, IF EXIST/IF DEFINED-фильтрации и regexp capture substitutions. Шесть действий ассоциаций хранятся независимо; отсутствие альтернативной команды не подменяет её основной командой.

Терминал объявляет `TERM=xterm-256color`, `COLORTERM=truecolor` для реализованных цветов и основных режимов. Полная эмуляция VT/xterm остаётся отдельной доработкой.

## Интерактивные параметры, list-файлы и импорт — R13.3

Выбор пункта сначала открывает один диалог для всех уникальных `{input:…}`. Повтор одинакового параметра использует одно значение. Допустимо до 16 полей; название до 256 байт, исходный текст до 4096 байт, введённое значение до 64 КиБ без NUL. Отмена оставляет команду невыполненной. Следующий шаг показывает источник, каталог и готовую команду; доступны выполнение, вставка в командную строку и отмена. История приложения не сохраняет готовые команды с интерактивными значениями и временными списками.

List-файлы создаются только при подготовке выбранной команды в уникальной папке `0700`, файлы — `0600`, без следования конечным ссылкам. Один тип списка создаётся один раз на команду; суммарно до 8 МиБ и до 100000 выбранных файлов на список. Текстовый LF-список отклоняет имена с CR/LF: для произвольных POSIX-имён используйте NUL-список, например `xargs -0 -n 1 printf '%s\\n' < {list0}`. Содержимое списка не содержит shell-кавычек: это данные для читающей программы. Временный путь вставляется с POSIX-кавычками. Файлы живут до завершения foreground-команды/возврата управляемого shell к prompt; вставленные в строку — до выполнения, замены или отмены строки. Выход приложения также удаляет списки. Фоновые дочерние программы должны прочитать список до завершения foreground-команды; длительное хранение пути не поддерживается.

Кнопка **«Импорт FarMenu.ini…»** в окне конфигурации явно читает выбранный обычный файл до 256 КиБ, UTF-8 или UTF-16 с BOM. Результат заменяет меню в редакторе, сохраняя ассоциации; запись на диск требует «Сохранить». При любой ошибке весь прежний буфер сохраняется. Ничего не исполняется при чтении, импорте или сохранении.

Импортируются заголовки `клавиша: Название`, вложенные `{` / `}`, разделители `--:`, буквы/цифры и F1–F24. Поддерживается одна строка команды на пункт. Переносятся отдельные аргументы `!`, `!.!`, ``!` ``, `!&`/`!&Q`, `!\`, `!\!.!`, переключатели `!#`/`!^`, `!?Название?начальный текст!`, list-параметры `!@!`, `!@UF!` и модификатор S. Цельные двойные кавычки вокруг параметра снимаются перед безопасной POSIX-подстановкой. List-файл всегда UTF-8, U допускается явно; F выбирает полный путь, без F — только имя. Windows-команды/пути автоматически не переводятся: перед сохранением проверьте каждую строку для macOS.

Импорт целиком отклоняет неподдерживаемые короткие имена, левую/правую панели, описания, real-path метасимволы, параметры list Q/A/W, некавыченный `!&q`, неоднозначное склеивание аргументов, несколько строк CommandX, Windows IF/FOR/REM и префикс @, `%VAR%`/`%UserVarN`/`%RegexGroup`, истории и вложенные выражения интерактивного ввода. Для них нужен ручной перенос в POSIX-скрипт. OEM/ANSI-кодировки требуют явного перекодирования. Это проверяемый импорт подмножества, не полная совместимость FarMenu.ini.

При реализации повторно прочитаны закреплённые `usermenu.cpp` (`ParseMenu`), [fnparse.cpp](https://github.com/FarGroup/FarManager/blob/1a6b02544b339615232078e0551463ef15b73ff9/far/fnparse.cpp) (`tokens`, `MakeListFile`, `InputVariablesDialog`), `filetype.cpp` (`GetFiletypeOpenMode`, шесть действий) и раздел `MetaSymbols` в `FarRus.hlf.m4` через GitHub. Использована семантика поведения; реализация независима и ограничена безопасным POSIX quoting.

## Постоянная shell-сессия и экран — R13.1/R13.2, 04.11.2026

Флажок **«Сохранять состояние shell»** выбирается до запуска. Командная строка и кнопка Shell используют одну отдельную интерактивную `/bin/zsh`: переменные, функции, aliases и cwd живут между командами до остановки/выхода. Пользовательские startup-файлы не загружаются; временный ZDOTDIR содержит только hooks приложения, пользовательские файлы не меняются. История zsh на диск не сохраняется; история команд приложения сохраняется как прежде. Обычный режим без флажка остаётся отдельным shell на команду, а обычная кнопка Shell использует shell пользователя.

Команды постоянной сессии выполняются в показанной папке **zsh**. **«Папка панели → shell»** выполняет буквальный `cd` только у свободного shell; **«Папка shell → панель»** явно открывает его папку на активной панели. Сам `cd` в постоянном shell не двигает панели. Для F2 и ассоциаций папки должны совпадать: иначе приложение требует явной синхронизации, чтобы `{name}` не указывало на другой одноимённый файл. Дополнение путей учитывает cwd выбранного режима. После выхода сохранённая папка shell очищается, новая сессия стартует в активной панели.

Ввод строки отключён во время работы программы и при незавершённом вводе в терминале; команда дополнительно проверяет, что foreground process group принадлежит shell. Готовность нового приглашения сообщается из zle-line-init после включения редактора строки, при пустом BUFFER и CONTEXT=start; precmd заранее сохраняет код завершения и cwd. Продолжение команды и вложенный vared не разрешают отправку из командной строки. Кадры ограничены и привязаны к идентификатору сессии. Для отмены строки Ctrl+C вызывает приватный ZLE-widget после уже отправленных байтов: он очищает BUFFER и возвращает отдельное подтверждение cleared без SIGINT, который мог бы сбросить очередь ввода. Кнопка Ctrl+C во время работы программы очищает непрочитанный ввод PTY и прерывает её foreground process group. После ручного ввода в работающую программу командная строка остаётся заблокирована при возврате к prompt: программа могла не прочитать этот текст. Подсказка предлагает Ctrl+C для явной очистки; ввод сразу после очистки также не разрешает склеить две команды. Управляемый zsh использует emacs-раскладку редактора строки. Чужой OSC7 не перемещает панели. Команды до 64 КиБ; NUL запрещён. Для многострочных/управляющих символов используется один закодированный `eval`, чтобы текст не стал управляющими клавишами PTY. Если вручную заменить hooks или сделать `exec` другой программы, интеграция состояния перестаёт действовать: завершите сессию и откройте новую.

Экран поддерживает SGR 16/256/RGB, bold/faint/italic/underline/inverse/hidden/strike и отдельные сбросы; приложение отображает атрибуты и учитывает масштаб шрифта при расчёте PTY. OSC0/2 и OSC7 разбираются как ограниченные метаданные без выполнения команд, открытия ссылок, записи clipboard или перемещения панелей. Реализованы видимость курсора, application cursor keys, bracketed paste, базовые ответы DSR/DA. Paste удаляет вложенный ESC, чтобы он не завершил защищённую вставку. При уменьшении высоты нижнее приглашение сохраняется, вытесненные основные строки попадают в ограниченную историю вместе со стилями.

Сегментация Swift объединяет потоковые combining/CJK/emoji (ZWJ, modifiers, flags, keycap); политика ширины приблизительная, ambiguous — одна ячейка, кластер до 64 байт. NSTextView не гарантирует точную геометрию каждой ячейки для любого шрифта. Изменение ширины обрезает строки, не выполняя reflow.
